# RESONA — 프로젝트 지침

라이브 공연의 음악과 관객 반응을 실시간으로 분석해 무대 연출 신호로 바꾸는 웹 애플리케이션입니다.

## 이 프로젝트의 핵심

> 음악이 "무엇을 연출할지"를 정하고, 관객 반응이 "그것을 얼마나 강하게 할지"를 정한다.

이 결합이 `lib/direction/translate.ts` 한 곳에 모여 있어야 합니다. 여러 파일에 흩어뜨리지 마십시오. 관객 값이 곱해지는 자리를 다른 사람이 바로 찾을 수 있어야 합니다.

## 기술 스택

- Next.js 15 App Router, TypeScript strict
- Tailwind CSS
- Web Audio API (AudioWorklet), Canvas 2D, 무대 씬만 WebGL2 (라이브러리 없이)
- Zustand
- Supabase (Postgres, Auth)
- Vercel

## 코딩 규칙

**실시간 값은 React 상태에 넣지 않습니다.** 매 프레임 바뀌는 분석값은 `useRef` 로 들고 캔버스에서 직접 읽습니다. 화면에 표시할 수치는 4프레임마다 한 번만 상태로 올립니다. 이것을 어기면 프레임이 떨어집니다.

**브라우저 API 를 쓰는 컴포넌트에는 `'use client'` 를 붙입니다.** Web Audio, getUserMedia, Canvas 는 모두 클라이언트 전용입니다.

**AudioContext 는 사용자 조작 시점에 만듭니다.** 브라우저 정책상 자동 시작이 막혀 있습니다. 이미 있으면 `resume()` 을 호출합니다.

**소스를 전환할 때 이전 노드를 반드시 끊습니다.** 끊지 않으면 소리가 겹치고 분석값이 오염됩니다.

**모든 분석 결과는 0~1 로 정규화합니다.** 예외는 BPM(숫자 그대로)과 센트로이드(Hz)입니다.

**씬은 색을 직접 쓰지 않습니다.** 색이 필요하면 팔레트의 역할 다섯 개(`bg` `deep` `base` `accent` `hot`)에서 가져옵니다. 씬 코드에 HEX 값을 박아 넣으면 팔레트를 바꿔도 그 자리만 남습니다. 콘솔 UI 의 색은 이와 별개로 CSS 변수에 고정합니다.

**관객 입력이 없어도 모든 기능이 동작해야 합니다.** 관객은 증폭기이지 전제 조건이 아닙니다. 새 코드를 쓸 때마다 관객을 끈 상태를 확인하십시오.

**공연 중에 쓰는 도구입니다.** 한 부분이 실패해도 화면은 계속 돌아야 합니다. 오류를 던져 렌더 루프를 멈추게 하지 마십시오.

## 신호처리 파라미터

`docs/05-signal-processing.md` 의 숫자는 기존 프로토타입에서 실제로 동작하던 값입니다. 추정값이 아닙니다. 바꾸려면 이유를 남기고 사용자에게 알리십시오.

특히 다음은 임의로 바꾸지 마십시오.

- 온셋 임계값 `중앙값 × 1.5 + 0.022`, 최소 간격 85ms
- BPM 빗살 가중치 `0.62 / 0.38 / 0.22`, 옥타브 접기 범위 72~182
- 관객 어택 1.5초 / 릴리스 3.0초 (이 비대칭이 중요합니다)
- 관객 보정 퍼센타일 5 / 95
- 크로마 평활 계수 0.90, `valence` 시상수 6초 / `arousal` 시상수 3초
- 팔레트 전환 시상수 2.5초

무대 씬(`03-screens.md`)의 숫자는 예외입니다. 이번에 새로 설계한 것이라 실행 기록이 없습니다. 화면을 보고 조정하되, 조정한 값을 명세에 되돌려 적으십시오.

## 확인 방법

수치가 맞는지보다 **화면이 음악과 맞아 보이는지**가 중요합니다. 단위 테스트로 판단할 수 없으므로, 기능을 구현한 뒤에는 실제로 음원을 재생해 확인하고 그 결과를 보고하십시오.

프레임 속도는 화면에 표시되는 fps 로 확인합니다. 30 아래로 떨어지면 그 자리에서 원인을 찾으십시오.

**색은 캔버스 평균으로 판정하지 마십시오.** 씬이 색을 어떻게 칠하느냐에 따라 평균이 크게 왜곡됩니다. 직조는 가는 실을 검은 바탕에 긋기 때문에 평균이 검정 쪽으로, 무대 씬은 가산 블렌딩이라 반대 방향으로 끌려갑니다. 팔레트 역할값(`base` `accent` `hot`)의 색상각과 채도를 직접 보거나, 굳이 화면을 재려면 밝은 픽셀 상위 10% 의 평균을 쓰십시오 (`05-signal-processing.md` 8-6절).

## 하지 않을 것

- 관객 카메라 프레임을 저장하거나 서버로 보내는 일
- 관객 개인 식별, 얼굴 인식
- 딥러닝 음원 분리 (지연 시간 때문에 배제했습니다)
- 서버 왕복이 필요한 실시간 분석
