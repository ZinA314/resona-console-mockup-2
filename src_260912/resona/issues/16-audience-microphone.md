## 목표

객석 마이크에서 박수와 환호를 재어 관객 에너지를 만든다. 카메라를 쓸 수 없는 공연장을 위한 두 번째 입력원이다.

## 배경

원본 프로토타입에는 없는 기능이다. 원본의 관객 입력은 카메라 얼굴 검출 하나뿐이었다. 상단의 `라인 / 마이크` 버튼은 **음원을 받는 입력 소스**이지 관객 측정이 아니다. 헷갈리기 쉬운 자리다.

카메라를 못 쓰는 공연장이 실제로 많다. 객석 촬영이 금지되거나, 조명이 어두워 얼굴이 잡히지 않거나, 카메라를 걸 자리가 없는 경우다. 그때도 무대는 가야 한다.

## 원본에서 가져다 쓸 것

관객 측정 자체는 원본에 없지만, **마이크를 여는 코드는 있다.** 01 소스 입력의 `startMic()` 이 그것이다.

```js
navigator.mediaDevices.getUserMedia({
  audio:{ echoCancellation:false, noiseSuppression:false, autoGainControl:false, channelCount:2 }
})
```

브라우저 기본 처리 셋을 끄는 것, 하울링을 막으려고 스피커로 되돌리지 않는 것, 권한 거부·장치 없음을 사유별로 안내하는 것까지 그대로 쓸 수 있다. 우리 구현의 소스 마이크도 같은 코드를 쓰고 있으니 거기서 가져와라.

## 지켜야 할 것

식은 명세에 있는 값 그대로 쓴다.

```
clapRaw  = 2000~8000Hz 구간의 트랜지언트 밀도
cheerRaw = 300~4000Hz 구간의 지속 에너지
raw = clapRaw × 0.6 + cheerRaw × 0.4
raw *= (1 - corr × 0.7)      // corr = 음악 스펙트럼과의 상관계수 0~1
```

**마이크 입력의 브라우저 기본 처리를 끈다.** `echoCancellation` · `noiseSuppression` · `autoGainControl` 셋 다 `false` 다. 켜 두면 박수가 잡음으로 지워지고 AGC 가 세기 차이를 뭉갠다 (`05-signal-processing.md` 34행).

**스피커로 되돌리지 않는다.** 하울링이 난다.

**음원 입력용 마이크와 다른 장치다.** 소스 패널의 마이크와 관객 패널의 마이크는 서로 다른 입력을 고르게 두어야 한다. 같은 장치를 두 곳에서 열지 않도록 한다.

화면에서도 둘을 구분해야 한다. 01 소스 입력의 마이크는 **무엇을 연출할지**를 정하는 쪽(무대 음향을 분석 대상으로 받는다)이고, 04 관객 패널의 마이크는 **얼마나 강하게 할지**를 정하는 쪽(객석 반응을 잰다)이다. 이름이 같아서 실제로 혼동이 일어난 자리다. 라벨을 각각 `라인 / 마이크` 와 `객석 마이크` 로 다르게 둔다.

## 완료 기준

- [ ] 음악만 크게 틀었을 때는 크게 오르지 않는다. 상관 감쇠가 도는 것을 이 대조로 확인한다
- [ ] 카메라 방식과 번갈아 켜도 보정이 각각 새로 잡힌다
- [ ] 관객 패널에서 마이크를 끄면 에너지가 0 으로 내려가고 연출은 그대로 돈다
- [ ] 20초 뒤 보정 완료가 뜬다
