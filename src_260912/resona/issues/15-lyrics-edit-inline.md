## 목표

이미 불러온 가사를 그 자리에서 고친다.

## 배경

증상이 둘인데 뿌리가 같다 (2026-09-07 확인).

- 표시 탭에서 `.lrc` 를 불러온 뒤 편집 탭으로 가면 원문 영역이 비어 있다. 거기에 한 줄을 적고 `파싱` 을 누르면 불러온 큐가 통째로 그 한 줄로 바뀐다 (스무 줄이 한 줄이 됨)
- 반대로 원문 영역에 직접 적어 `파싱` 한 뒤 새 파일을 불러오면, 큐는 새 파일로 바뀌는데 **원문 영역에는 직전에 적은 글이 그대로 남는다**

- 원문 영역에 가사가 있는 상태에서 시각이 붙은 줄 하나를 적고 `파싱` 을 누르면, 시각이 없던 줄이 전부 사라진다

앞의 둘은 원문 영역과 큐가 따로 놀아서 생긴다. 셋째는 다른 원인이고, 명세가 잘못 적혀 있어서 생긴다.

**`파싱` 이 시각 없는 줄을 버리도록 규정한 것이 잘못이다.** 지금 명세는 「`[mm:ss.xx]` 가 붙은 줄만 큐로 만듭니다」인데, 그러면 `길이에 균등 배분` 이 나눌 대상이 파싱 직후에 이미 사라진다. 두 기능이 서로를 무효로 만든다. 리허설에서 흔한 경우인 "앞부분만 찍어 두고 뒤는 아직" 도 다룰 수 없다.

**원인은 파싱이 아니라 이음새다.** 파싱이 "원문 영역의 내용으로 큐를 만든다" 인 것은 맞다. 빠진 것은 지금 큐가 원문 영역에 실려 있지 않다는 점이다.

리허설에서 실제로 벌어지는 일은 "가사 파일은 있는데 한 줄이 틀렸다" 이지 "처음부터 만든다" 가 아니다. 고치는 경로가 없으면 편집기가 있어도 쓰지 못한다.

## 작업

### 원문 영역과 큐 잇기

- [ ] 큐가 바뀌면 원문 영역을 그 큐의 LRC 원문으로 다시 그린다
- [ ] 계기마다 "손댄 상태" 를 존중할지가 다르다. 아래 표대로 가른다
- [ ] 손댄 상태에서는 `파싱` 버튼 옆에 미반영 표시를 둔다
- [ ] `되돌리기` — 원문 영역을 지금 큐의 내용으로 되돌리고 손댄 상태를 푼다
- [ ] `파싱` 의 뜻은 바꾸지 않는다. 원문 영역 내용으로 큐를 통째로 바꾼다. **병합하지 않는다** — 같은 시각이 겹치고 순서가 꼬인다

| 큐가 바뀐 계기 | 손댄 상태일 때 |
|---|---|
| **파일 로드** | **갈아 끼운다.** 손댄 글을 버리고 새 파일 원문으로 채운 뒤, 손댄 상태를 푼다 |
| 탭 모드로 시각 찍기 | 다시 그리지 않는다 |
| 줄 목록에서 고치거나 지우기 | 다시 그리지 않는다 |

**파일 로드만 예외인 이유가 있다.** 파일을 여는 것은 "이 가사로 바꿔라" 라고 사용자가 직접 말한 행위다. 그 자리에서 원문이 갈리지 않으면 화면에 보이는 글과 실제 큐가 어긋난 채로 남고, 그다음 `파싱` 이 방금 연 파일을 지운다. 손댄 글을 지키고 싶으면 파일을 열기 전에 `파싱` 을 누르면 된다. 리허설 중에 대화상자를 띄워 묻지 않는다.

### 파싱이 줄을 버리지 않게

- [ ] 큐의 줄은 시각이 없을 수 있다 (`time: number | null`)
- [ ] `파싱` 은 비어 있지 않은 모든 줄을 큐에 넣는다. `[mm:ss.xx]` 가 붙은 줄은 시각을 채우고, 안 붙은 줄은 **시각 미정**으로 둔다
- [ ] 줄 목록에서 시각 미정 줄은 타임스탬프 자리에 `--:--.--` 를 흐리게 둔다
- [ ] `길이에 균등 배분` 은 **시각 미정 줄만** 대상으로 한다. 이미 시각이 있는 줄은 건드리지 않는다
- [ ] 탭 모드는 시각 미정 줄부터 순서대로 찍는다
- [ ] 재생 중에는 시각 미정 줄을 건너뛴다. 표시 탭과 씬에 뜨지 않는다
- [ ] `LRC 내보내기` 는 시각 미정 줄을 빼고 내보내되, 뺀 줄이 몇 개인지 알린다

**균등 배분을 "미정 줄만" 으로 두면 버튼 하나로 두 경우가 다 풀린다.** 처음부터 만들 때는 모든 줄이 미정이므로 전부 배분되고, 섞여 있을 때는 빈자리만 채운다. 앞서 명세에 적힌 "균등 배분이 기존 시각을 버린다" 는 이 규칙으로 바뀐다.

### 줄 목록에서 고치기

- [ ] 가사 글자 인라인 편집 — 줄의 글자를 누르면 그 자리에서 고친다. `Enter` 확정, `ESC` 취소
- [ ] 줄 삭제 — 줄 끝의 `×`
- [ ] 줄 추가 — `현재 시각에 줄 추가`. 재생 위치에 빈 줄을 넣고 곧바로 글자 입력으로 들어간다
- [ ] 고치거나 지운 결과가 원문 영역과 표시 탭에 즉시 반영된다

## 완료 기준

- [ ] `.lrc` 를 불러오고 편집 탭으로 가면 원문 영역에 그 원문이 들어 있다
- [ ] 그 아래에 한 줄을 더 적고 `파싱` 을 누르면 열 줄이 열한 줄이 된다. **원문 영역에 기존 줄이 실려 있어서 그렇게 되는 것이지, 파싱이 병합해서가 아니다.** 원문을 통째로 지우고 한 줄만 남긴 뒤 파싱하면 그 한 줄만 남는 것이 맞다
- [ ] 줄을 눌러 글자를 고치면 표시 탭의 가사도 바뀐다
- [ ] 줄을 지우면 줄 수가 하나 줄고, 내보낸 `.lrc` 에도 그 줄이 없다
- [ ] 원문 영역에 타이핑하는 도중에 탭 모드로 시각을 찍어도 타이핑한 글이 사라지지 않는다
- [ ] 원문 영역에 직접 적어 `파싱` 한 뒤 다른 `.lrc` 를 불러오면 **원문 영역이 새 파일 내용으로 갈린다.** 앞서 적은 글이 남아 있지 않고, 미반영 표시도 꺼진다
- [ ] 타임스탬프 직접 수정과 전체 오프셋이 불러온 큐에도 걸린다
- [ ] 시각이 붙은 열 줄과 안 붙은 열 줄을 섞어 붙여 넣고 `파싱` 하면 **스무 줄이 다 남는다.** 뒤 열 줄은 `--:--.--` 로 뜬다
- [ ] 이어서 `길이에 균등 배분` 을 누르면 **미정이던 열 줄에만 시각이 붙고, 이미 있던 열 줄은 그대로다**
- [ ] 시각 미정 줄이 남아 있는 채로 재생해도 표시 탭이 그 줄에서 멈추거나 비지 않는다

## 구현 주의

**클릭 한 번에 두 가지 일을 걸지 않는다.** 줄의 타임스탬프를 누르면 그 시각으로 탐색하고, 글자를 누르면 편집으로 들어간다. 재생 중에 가사를 고치려다 재생 위치가 튀면 리허설에서 쓸 수 없다.

인라인 편집 중에는 `Space` 와 `ESC` 가 편집기 것이다. 전역 단축키 처리기의 `isTyping` 갈림이 이 자리도 덮는지 확인한다.
