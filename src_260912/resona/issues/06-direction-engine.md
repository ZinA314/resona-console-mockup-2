## 목표

음악과 관객을 결합해 연출 파라미터를 만든다. **이 이슈가 프로젝트의 이유다.**

이 이슈는 5단계-A 다. 곡의 분위기 판정과 색 팔레트는 5단계-B(`11-mood-palette.md`)에서 이어서 한다.

## 배경

이 프로젝트의 핵심 명제는 하나다.

> 음악이 "무엇을 연출할지"를 정하고, 관객 반응이 "그것을 얼마나 강하게 할지"를 정한다.

음악만 쓰면 오디오 비주얼라이저에 그치고, 관객만 쓰면 반응 미터기에 그친다. 기존 프로토타입은 두 신호를 각각 잘 측정했지만 결합하지 않았고, 그래서 관객 값이 화면 연출에 아무 영향을 주지 못했다. 이 이슈가 그 자리를 채운다.

## 작업

- [ ] `lib/direction/state.ts`: 음악 상태 판정 (SILENT / CALM / GROOVE / BUILD / PEAK / BREAK)
- [ ] **전이 규칙** — 최근 1.2초 창에서 과반을 차지한 상태로 전환하고, 바뀐 뒤 최소 1.2초 유지 ("1.2초 연속"이 아니다)
- [ ] `rmsSlow` (시정수 0.4초) 추가. `PEAK` 판정에만 쓴다
- [ ] **`PEAK_TH` 와 `SLOPE_TH` 를 실측으로 정하고 명세에 되돌려 적는다** (실측 결과 0.434 · 0.008)
- [ ] 검사 순서에서 `BUILD` 를 `PEAK` 보다 앞에 둔다
- [ ] `BUILD` 조건은 `rmsSlope > 0.008` 하나. `fluxRise` 를 쓰지 않는다
- [ ] `SILENT` 은 즉시 채택, `BREAK` 은 즉시 채택 + 최소 0.8초 유지
- [ ] 상태 전이 펄스 (`transitionPulse`)
- [ ] `lib/direction/translate.ts`: 결합 규칙과 파라미터 산출
- [ ] 실효 관객값 `audEff = 관객에너지 × 영향력`
- [ ] 가산 증폭 `final = base × (1 + audEff × gain)`
- [ ] 파라미터 7종 산출 (density / scale / speed / brightness / hue / expansion / glitch)
- [ ] `musicOnly` 병행 반환 (관객 기여분 시각화용)
- [ ] 08 연출 파라미터 패널: 두 층 막대 (아래 흰색 = 음악만, 위 청록색 = 관객 포함)
- [ ] 관객 영향력 슬라이더 연동, A 키로 0% 토글
- [ ] 모든 씬이 `DirectionParams` 를 읽어 그리도록 개편

## 완료 기준

- [ ] 영향력 0% 에서 관객이 움직여도 화면이 변하지 않는다
- [ ] 영향력 100% 에서 관객 에너지를 올리면 화면이 눈에 띄게 강해진다
- [ ] **관객 입력을 아예 꺼도 음악 연출이 그대로 동작한다**
- [ ] 08 패널의 두 층 차이가 관객 반응에 따라 벌어졌다 좁아진다
- [ ] 상태 이름이 곡 진행에 따라 바뀌고 1.2초보다 짧게 깜빡이지 않는다
- [ ] 센 구간에서 `PEAK` 이 실제로 잡힌다 (킥마다 끊기지 않는다)
- [ ] **`GROOVE` 구간이 `PEAK` 으로 잡히지 않는다.** 문턱이 낮으면 온 구간이 `PEAK` 이 된다
- [ ] 빌드업 구간에서 `BUILD` 가 잡힌다
- [ ] **`PEAK` 이 빌드업 후반을 잡아먹지 않는다.** 기대 시각보다 몇 초 이르게 시작하면 검사 순서를 확인한다
- [ ] 문턱 두 개를 실측으로 정하고 근거 분포를 명세에 적었다
- [ ] 음악이 뚝 끊기면 화면이 곧바로 반응한다 (`BREAK` 이 1.2초 늦지 않는다)

세 번째가 특히 중요하다. 공연 현장에서 카메라가 말썽을 부려도 무대는 계속 가야 한다.

## 검증

`synth/test-03-buildup.wav` 로 상태 판정을 확인한다. 시각이 몇 초 어긋나는 것은 정상이고 순서가 맞는지를 본다.

| 시각 | 기대 상태 | 비고 |
|---|---|---|
| 0~4초 | SILENT | |
| 4~16초 | CALM | |
| 16~30초 | GROOVE | |
| 30~42초 | BUILD | `rmsSlope > 0.02` · `fluxRise > 1.15` |
| 42~50초 | PEAK | 판정에 `rmsSlow` 를 쓴다 |
| 50~54초 | **SILENT** | 이 음원의 브레이크 구간은 완전 무음이라 `SILENT` 가 맞다 |
| 54~62초 | GROOVE | |

`BREAK` 은 이 음원으로 확인할 수 없다. 드럼만 빠지고 패드가 남는 실제 음악에서 따로 본다.

관객 결합은 시뮬레이션 슬라이더를 밀면서 08 패널의 두 층을 본다.

**시뮬만으로 끝내지 않는다.** 시뮬은 자동 보정을 건너뛰므로(F-303), 시뮬로만 확인하면 보정 경로가 한 번도 실행되지 않는다. 카메라를 켜고 같은 확인을 한 번 더 한다.

## 구현 주의

결합을 한 함수에 모은다. 여러 파일에 흩어뜨리면 나중에 어디서 합쳐지는지 찾을 수 없다.

`hue` 의 gain 은 0 이다. 관객이 색까지 바꾸면 연출가가 곡마다 잡아 둔 색채 계획이 무너진다. 관객은 강도를 바꾸고 색은 음악이 정한다.

곱이 아니라 가산 증폭인 이유는, 곱으로 하면 관객이 조용할 때 화면이 꺼져 버리기 때문이다.
