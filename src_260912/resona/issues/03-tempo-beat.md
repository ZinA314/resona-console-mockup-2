## 목표

BPM 을 추정하고 비트를 추적한다. 이 프로젝트에서 기술적으로 가장 까다로운 부분이다.

## 배경

화면 갱신 주기는 기기마다 다르므로, 분석 주기를 고정하지 않으면 같은 곡이 기기에 따라 다른 BPM 으로 잡힌다. 그래서 온셋 세기를 100Hz 고정 버퍼에 따로 쌓는다.

자기상관의 단일 최대값만 쓰면 8분음표 주기나 2마디 주기에 걸리는 일이 잦다. 배음까지 함께 보는 빗살 점수가 이 문제를 막는다.

## 작업

- [ ] 온셋 엔벨로프를 100Hz 고정 주기 원형 버퍼에 적재 (누적값은 매 구간 0.4배로 감쇠)
- [ ] 0.4초마다, 버퍼가 400 샘플 이상일 때 BPM 추정 실행
- [ ] 평균 제거 후 자기상관 계산 (최대 지연의 4배까지)
- [ ] 빗살 점수: `r[lag] + r[lag×2]×0.62 + r[lag×3]×0.38 + r[lag×4]×0.22`
- [ ] 템포 연속성 가중: `score *= 1 + 0.30 × bpmConf × exp(-|후보 - 이전BPM| / 5.5)` — `bpmConf` 를 곱하지 않으면 초반에 우연히 앞선 후보가 스스로를 강화해 실행마다 다른 값에 고착된다
- [ ] 옥타브 접기: 72 미만이면 2배, 182 초과면 절반
- [ ] 갱신 폭 구분: 차이 2.2 BPM 초과면 `lerp(0.30)`, 이하면 `lerp(0.10)`
- [ ] 신뢰도(`bpmConf`) 산출과 표시
- [ ] 비트 트래킹: 주기 예측, 30% 이내 온셋에서 위상 스냅, 밀렸을 때 재동기화
- [ ] 4박 마디 카운트
- [ ] 탐색 막대 위에 비트 눈금 표시 (마디 첫 박은 길게)
- [ ] 데모 신스 구현 (킥·스네어·하이햇·베이스·패드, 120 BPM)
- [ ] **분석 상태 초기화** — 새 파일 로드·정지·탐색·소스 전환 시 엔벨로프 버퍼와 템포 상태를 전부 비운다 (일시정지는 제외)

## 완료 기준

- [ ] `test-02` 에서 BPM 이 126~130 안에 들어온다
- [ ] **64 나 256 으로 잡히지 않는다**
- [ ] 마디가 4박마다 올라간다
- [ ] 비트 표시가 킥 소리와 어긋나지 않는다
- [ ] 데모 신스를 켜면 120 근처로 수렴한다
- [ ] 실제 음악 세 곡에서도 절반이나 두 배로 잡히지 않는다
- [ ] **같은 곡을 여러 번 틀어도 같은 값이 나온다** (`knockout.mp3` 를 3회 이상 반복)
- [ ] **재생 시작 후 4~5초 동안 BPM 이 비어 있다.** 시작하자마자 값이 뜨면 이전 재생의 버퍼가 남은 것이다

## 검증

**`synth/test-02-beat-128bpm.wav`** — 정답이 128 BPM 이다. 같은 방식으로 미리 분석해 본 결과 127.6 이 나왔으므로 그 근처면 정상이다.

**`music/` 세 곡** — 실제 음악에서도 안정적으로 잡히는지 본다. `knockout.mp3` 가 비트가 가장 뚜렷하다.

## 실패했을 때 볼 곳

절반이나 두 배로 잡히면 빗살 가중치나 옥타브 접기가 빠진 것이다. 값이 계속 흔들리면 템포 연속성 가중이나 갱신 폭 구분이 빠진 것이다.
