## 목표

`라인 / 마이크` 를 음원 입력원으로 쓸 수 있게 한다. 지금 이 버튼은 비활성 상태이고 「2단계에서 구현합니다」 툴팁이 붙어 있다.

## 배경

**이것은 「이후 과제」가 아니라 빠진 기능이다.** F-102 는 명세에 정식으로 있고 수용 기준까지 적혀 있는데, `07-roadmap.md` 의 어느 단계에도 배치되지 않았다. 같은 묶음의 F-103(데모 신스)은 2단계에 들어가 있으나 F-102 만 빠졌다. 그래서 1단계에서 「2단계에서 구현」으로 미뤄진 뒤 2단계 작업 목록에 없어 그대로 남았다.

로드맵을 쓴 쪽의 누락이다. 구현이 잘못된 것이 아니다.

여덟 단계를 다 마친 지금, 화면에 「2단계에서 구현합니다」가 떠 있는 것 자체가 어긋난다.

## 왜 필요한가

공연장에서 콘솔에 곡 파일이 없는 경우가 흔하다. 밴드가 실연하거나, 음향 감독이 자기 장비에서 재생하거나, 리허설에서 즉흥으로 연주할 때다. 그때 콘솔은 라인 출력이나 객석 마이크에서 소리를 받아 분석해야 한다. 파일 재생만 되는 콘솔은 미리 준비한 음원이 있을 때만 쓸 수 있다.

- [ ] 소스 라벨을 `LINE IN` 으로 바꾸고, 트랜스포트의 위치 표시는 경과 시간으로 둔다

## 원본에서 가져다 쓸 것

원본 `resona.html` 의 `startMic()` 이 이 일을 그대로 한다. 새로 설계하지 말고 옮겨라.

```js
navigator.mediaDevices.getUserMedia({
  audio:{ echoCancellation:false, noiseSuppression:false, autoGainControl:false, channelCount:2 }
})
```

권한 거부(`NotAllowedError`)와 장치 없음(`NotFoundError`)을 갈라 안내하는 문구, `file://` 로 열었을 때의 안내까지 원본에 있다.

## 지켜야 할 것

**브라우저 기본 처리 셋을 끈다.** 에코 제거·잡음 억제·자동 이득 조절이다. 켜 두면 공연 음향이 그대로 측정되지 않는다. 특히 AGC 는 곡의 셈여림을 뭉개서 `arousal` 판정을 망친다.

**스피커로 되돌리지 않는다.** 하울링이 난다. 분석 경로에만 물린다.

**소스를 바꿀 때 이전 노드를 끊는다.** 끊지 않으면 소리가 겹치고 분석값이 오염된다 (`CLAUDE.md`).

**소스 전환은 전체 초기화다.** 파일 ↔ 마이크 ↔ 데모 를 오갈 때 `bpm` 을 포함해 분석 버퍼를 전부 비운다 (`05-signal-processing.md` 3-5절). 탐색과 달리 부분 초기화가 아니다.

**끝나는 시각이 없는 입력이다.** 파일과 달리 길이가 없으므로, 구간 반복(F-202)과 가사 큐의 `길이에 균등 배분` 은 이 소스에서 쓸 수 없다. 해당 버튼을 잠그고 사유를 표시한다.

## 완료 기준

- [ ] 마이크를 켜고 소리를 내면 RMS 값이 즉시 반응한다 (F-102 수용 기준)
- [ ] 음악을 틀어 주면 BPM 이 잡히고 비트가 화면과 맞는다
- [ ] 파일 재생 중에 마이크로 전환하면 이전 소리가 겹치지 않는다
- [ ] 마이크에서 파일로 되돌아오면 BPM 이 새로 잡힌다
- [ ] 권한을 거부하면 사유가 화면에 뜨고 다른 입력을 권한다
- [ ] 스피커에서 하울링이 나지 않는다
- [ ] 이 소스에서는 구간 반복과 균등 배분 버튼이 잠겨 있고 이유가 보인다
