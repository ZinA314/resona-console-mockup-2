## 목표

무대에 걸 화면을 만든다. **여기까지 오면 이 프로젝트를 남에게 보여 줄 수 있다.**

## 배경

지금까지 만든 씬은 전부 진단용이다. 직조는 분석이 제대로 도는지 곡의 진행을 직물로 남겨 보는 화면이고, 스펙트럼과 관객 씬도 마찬가지다. 원본 프로토타입도 그랬다. 미니멀 아트워크이지 콘서트 무대 영상이 아니다.

무대 화면은 성격이 다르다. 값을 읽는 화면이 아니라 느끼는 화면이다. 숫자·눈금·라벨을 하나도 그리지 않는다. 관객이 보는 화면에 진단 정보가 섞이면 그 순간 무대가 아니라 계기판이 된다.

**Canvas 2D 로는 안 된다.** `shadowBlur` 로 글로우를 흉내 내면 입자 수백 개에서 이미 프레임이 무너진다. 이 씬만 WebGL2 로 그리고 나머지 다섯 씬은 Canvas 2D 를 그대로 둔다. 라이브러리는 쓰지 않는다. 필요한 것이 전체 화면 사각형 하나와 점 그리기뿐이라 Three.js 를 얹으면 번들만 커진다.

- [ ] WebGL2 를 못 쓰는 브라우저에서는 씬 버튼을 비활성화하고 사유를 적는다

## 완료 기준

- [ ] **잔잔한 곡과 신나는 곡의 화면이 서로 다른 곡의 것으로 보인다**
- [ ] 잔잔한 곡에서 색이 크게 번지고 느리게 흐른다
- [ ] 신나는 곡에서 입자가 빠르게 돌고 윤곽이 또렷해진다
- [ ] 비트마다 입자가 바깥으로 퍼진다
- [ ] 빛 번짐이 보인다. 입자가 겹치는 자리가 더 밝다
- [ ] 팔레트를 바꾸면 화면 색이 통째로 바뀐다
- [ ] 화면에 숫자·눈금·라벨이 하나도 없다
- [ ] 잔잔한 구간에서 화면이 찢어지지 않는다
- [ ] 관객 에너지를 올리면 입자가 바깥으로 퍼지고 화면이 조금 날카로워진다
- [ ] **1920×1080 출력 창에서 60fps 를 유지한다**
- [ ] 직조 씬을 열면 예전과 똑같이 나온다. 무대 씬을 만들면서 직조가 망가지지 않았다

## 남은 확인

구현이 끝난 뒤에도 아래 둘은 따로 재야 합니다.

- [ ] **관객을 올렸을 때 입자가 실제로 퍼지는지 눈으로 본다.** 배선만 확인하는 것으로는 부족하다. 시뮬을 켜고 영향력을 0% 와 100% 로 오가며 반경 변화를 본다. 이 프로젝트의 핵심 명제가 화면에 나타나는 자리다
  - **p95 반경이 +8% 이상, 여덟 쌍 중 여섯 쌍 이상 증가해야 통과다.** 밝기 가중 평균으로 재지 않는다 — 점 크기 변화에 오염된다 (`docs/03-screens.md` 무대 씬 절)
  - 시뮬 모드에는 손잡이가 둘(`시뮬 수동`, `관객 영향력`)이다. 순서로 잡지 말고 `id` 로 잡는다
- [ ] **컨텍스트 손실을 실제로 만들어 본다.** `gl.getExtension('WEBGL_lose_context').loseContext()` 로 재현한다. 다음 프레임에 복구되는지, 그 사이 화면이 검게 되지 않는지 확인한다
  - 무대 씬의 캔버스는 DOM 에 붙어 있지 않아 밖에서 잡을 수 없다. **검증할 동안만 `window` 에 컨텍스트를 임시로 노출하고, 끝나면 되돌린다**
  - 컨텍스트를 여러 개 만들어 회수를 유도하는 방법은 통하지 않는다. 크롬이 무대 씬의 컨텍스트를 회수하지 않는다

## 검증

`music/knockout.mp3` 로 비트 확산을 본다. 잔잔한 곡 한 개를 따로 준비해 몽환 쪽 끝을 본다.

07 패널의 `몽환도 고정` 을 0 과 1 로 번갈아 두고 같은 곡에서 화면이 어떻게 달라지는지 확인한다. 이것이 가장 빠른 검증법이다.

`입자 수 상한` 을 8000 으로 올리고 fps 가 얼마나 떨어지는지 재 둔다. 공연장 노트북이 더 느릴 수 있다.

## 구현 주의

**색은 캔버스 평균으로 재지 않는다.** 무대 씬은 가산 블렌딩이라 평균이 밝은 쪽으로 왜곡된다. 팔레트 역할값을 직접 보거나 밝은 픽셀 상위 10% 의 평균을 쓴다 (`05-signal-processing.md` 8-6절).

**블룸은 1/4 해상도에서 한다.** 원본 해상도로 블러하면 프레임이 절반으로 떨어진다. 어차피 흐려지는 것이라 해상도를 줄여도 눈에 띄지 않는다.

**입자 상태를 저장하지 않는다.** 위치를 프레임 사이에 들고 다니려면 텍스처를 번갈아 쓰는 구조가 필요하고 코드가 세 배로 늘어난다.

**이 이슈의 수치는 실측값이 아니다.** 직조와 달리 원본에 없던 것이라 근거가 되는 실행 기록이 없다. 초기값으로 쓰되, 화면을 보고 조정한 다음 그 값을 `docs/03-screens.md` 에 되돌려 적는다.
