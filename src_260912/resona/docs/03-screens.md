# 03. 화면 명세

## 1. 화면 구성

화면은 두 벌입니다. 오퍼레이터가 보는 **콘솔**과 관객이 보는 **출력**입니다.

```
┌─────────────────────────────────────────────────────────┐
│ 상단 바 — 로고 · 입력상태 · BPM · RMS · 연동상태 · 시계    │
├──────────────┬──────────────────────────┬───────────────┤
│              │                          │               │
│  왼쪽 레일    │      중앙 무대 (STAGE)     │  오른쪽 레일   │
│              │                          │               │
│ 01 소스 입력  │   현재 씬이 그려지는 곳      │ 06 씬 선택     │
│ 02 스템      │   (콘솔 안 미리보기)        │ 07 씬 파라미터  │
│ 03 가사 큐    │                          │ 08 연출 파라미터│
│ 04 관객 입력  │                          │ 09 분석 리드아웃│
│ 05 팔레트     │                          │ 10 외부 연동   │
│              │                          │ 11 단축키      │
├──────────────┴──────────────────────────┴───────────────┤
│ 하단 트랜스포트 — 재생·정지·탐색막대·시각·반복구간          │
└─────────────────────────────────────────────────────────┘
```

출력 창은 중앙 무대만 전체 화면으로 띄운 것입니다. 조작 요소가 없습니다.

**두 화면은 목적이 다릅니다.** 콘솔은 오퍼레이터가 값을 읽는 곳이고, 출력은 관객이 보는 곳입니다. 직조·스펙트럼처럼 값이 맞는지 확인하는 씬과 무대에 걸 씬을 같은 것으로 쓰면 어느 쪽도 제 역할을 못 합니다. 씬마다 어느 화면을 위한 것인지 4절에 표시했습니다.

## 2. 시각 언어

공연 콘솔이므로 어두운 배경을 전제로 합니다. 객석이 어두운 상태에서 오퍼레이터의 눈이 부시지 않아야 하고, 값을 빠르게 읽을 수 있어야 합니다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--void` | `#000000` | 무대 배경 |
| `--panel` | `#0A0A0A` | 패널 바탕 |
| `--panel2` | `#111110` | 패널 안쪽 구획 |
| `--rule` | `#222220` | 경계선 |
| `--bone` | `#E8E4DC` | 기본 글자 |
| `--dim` | `#6E6B64` | 보조 글자 |
| `--alert` | `#FF2A00` | 지금 일어나는 일 (비트, 온셋, 경고) |
| `--cyan` | `#7FD7D0` | 관객에서 온 값 |

**색으로 출처를 구분합니다.** 음악에서 온 값은 흰색 계열, 관객에서 온 값은 청록색으로 그립니다. 화면만 보고도 두 신호가 어디서 합쳐지는지 보이게 하려는 의도입니다.

글꼴은 수치용 고정폭(IBM Plex Mono)과 제목용 압축체(Barlow Condensed)를 씁니다. 모서리는 둥글리지 않습니다.

**위 표는 콘솔의 색입니다. 무대 화면의 색은 팔레트에서 옵니다.** 콘솔은 어두운 회색과 청록·빨강 두 강조색으로 고정하고, 씬이 그리는 색은 곡의 분위기에 따라 바뀝니다. 두 체계를 섞지 마십시오. 콘솔 UI 가 곡마다 색을 바꾸면 값을 읽기 어려워집니다. 팔레트 규칙은 `05-signal-processing.md` 8절에 있습니다.

## 3. 패널별 명세

**패널 번호는 화면 배치 순서를 따릅니다.** 왼쪽 레일을 위에서 아래로 01~05, 오른쪽 레일을 위에서 아래로 06~11 입니다. 번호가 곧 눈으로 훑는 순서이므로, 나중에 패널을 더할 때도 뒤에 붙이지 말고 그 자리의 번호를 쓰고 뒤를 밀어야 합니다.

이 문서의 절 순서도 번호 순서와 같게 유지합니다.


### 상단 바

왼쪽부터 로고, 입력 상태, BPM, RMS, 관객 에너지, 연동 상태, 시계 순으로 배치합니다.

- 입력 상태: LED 점 하나와 문구. `신호 없음` / `파일` / `마이크` / `데모`
- BPM: 정수 세 자리. 신뢰도가 **0.45 미만이면 흐리게**, **0.20 미만이면 값 대신 `---`** 를 보여 줍니다. 근거가 사라진 수치를 그대로 두면 읽는 사람이 아직 유효한 값으로 오해합니다. 두 문턱은 09 리드아웃과 같습니다 (아래 「BPM 표시 문턱」)
- 관객 에너지: 0.00~1.00 과 함께 청록색 막대를 붙입니다
- 연동 상태: `연결 안 됨` / `연결됨` / `재연결 중`

### 01 소스 입력

- 큰 드롭 영역. 문구는 `음원 파일 로드`, 아래 작은 글씨로 `MP3 · WAV · FLAC · 끌어다 놓거나 클릭`
- 버튼 두 개: `라인 / 마이크`, `데모 신스`
- 안내 문구: `파일은 브라우저 안에서만 디코딩됩니다. 서버 업로드·저장 없음.`
- 오류가 나면 이 자리에 붉은 글씨로 사유를 적습니다

#### 라인 / 마이크를 골랐을 때 (F-102)

- 소스 줄에 `LINE IN` 과 장치 이름을 답니다. 파일과 달리 길이가 없으므로 길이 자리에 장치 이름이 옵니다
- 입력 장치가 둘 이상이면 고르는 칸이 나타납니다. 오디오 인터페이스가 여럿 붙는 현장이 있습니다. **이름은 권한을 받은 뒤에야 채워지므로** 마이크가 켜진 다음에만 보입니다
- 버튼을 다시 누르면 장치를 놓습니다. 트랜스포트의 `정지` 도 같습니다

**끝나는 시각이 없는 입력이라 잠기는 것이 셋입니다.**

| 자리 | 왜 |
|---|---|
| 재생 / 일시정지 | 흐르는 입력이라 멈추거나 되감을 것이 없습니다. 대신 `정지` 가 장치를 놓습니다 |
| 구간 반복 `A` `B` (F-202) | 되돌아갈 지점이 없습니다 |
| 가사 `균등 배분` | 나눌 길이가 없습니다. 탭 모드로 찍습니다 |

**잠그되 눌리게 두고 사유를 띄웁니다.** 눌러도 아무 일이 없으면 고장으로 보입니다. 04 관객 패널의 `마이크` 버튼(F-302)과 같은 원칙입니다.

트랜스포트의 위치 표시는 켠 뒤 흐른 시간입니다.

### 02 스템

네 칸을 2×2 로 배열합니다. 각 칸에 값, 이름, 출처 설명, 레벨 막대를 둡니다.

| 칸 | 이름 | 출처 설명 |
|---|---|---|
| 0 | DRUMS | 트랜지언트 · 2–8k |
| 1 | BASS | 20–250Hz |
| 2 | VOCAL | MID 채널 · 200–4k |
| 3 | OTHER | SIDE 채널 · 잔여 |

머리말에 현재 모드를 표시합니다. `의사분리` 또는 `실제 스템`. 칸을 클릭하면 그 트랙을 음소거합니다.

### 03 가사 큐

탭 두 개로 나눕니다. `표시` 와 `편집` 입니다.

#### 표시 탭

- LRC 파일 드롭 영역
- 현재 줄과 다음 줄을 두 줄로 표시하고, 현재 줄에는 진행 막대를 겹칩니다
- 줄 번호와 전체 줄 수를 작게 표시합니다

#### 편집 탭 (LRC 편집기)

가사 파일을 미리 만들어 오지 못한 곡이 리허설에 올라옵니다. 그 자리에서 만들 수 있어야 합니다.

- **원문 입력 영역** — LRC 원문을 붙여 넣거나, 타임스탬프 없는 순수 가사를 줄 단위로 붙여 넣습니다. **지금 큐를 그대로 비춥니다** (아래 「원문 영역과 큐」)
- `파싱` — 원문 영역의 내용으로 큐를 통째로 바꿉니다. **비어 있지 않은 모든 줄이 큐가 됩니다** — 시각이 안 붙은 줄은 시각 미정으로 남습니다
- `되돌리기` — 원문 영역을 지금 큐의 내용으로 되돌리고 손댄 상태를 풉니다. 손댄 상태일 때만 보입니다
- `길이에 균등 배분` — **시각 미정 줄에만** 시각을 채웁니다. 이미 시각이 있는 줄은 건드리지 않습니다
- **`탭 모드`** — 켜면 재생 중 `Space` 가 "현재 줄에 지금 시각 찍기" 로 바뀌고, 찍을 때마다 다음 줄로 내려갑니다
  - **켜는 순간 화면 상단에 붉은 배너를 띄웁니다.** `탭 모드 — Space 는 타임스탬프 찍기 · ESC 로 나가기`
  - `Space` 는 평소 재생과 일시정지에 쓰는 키입니다. 배너 없이 뜻을 바꾸면 공연 중에 재생을 멈추려다 가사를 망가뜨립니다. 이 배너는 선택 사항이 아닙니다
  - 탭 모드에서 벗어나는 방법은 `ESC` 와 토글 해제 두 가지입니다
- **줄 목록** — 한 행이 `▸ 시각 가사 ×` 입니다. `▸` 는 그 시각으로 탐색하고, 시각 칸은 직접 고치며, 가사를 누르면 그 자리에서 글자를 고칩니다(`Enter` 확정 · `ESC` 취소). `×` 는 그 줄을 지웁니다. 재생 중에는 현재 줄을 강조합니다
- `현재 시각에 줄 추가` — 재생 위치에 빈 줄을 넣고 곧바로 글자 입력으로 들어갑니다
- **전체 오프셋** — `−0.1s` `+0.1s` 버튼. 가사가 전체적으로 이르거나 늦을 때 한 번에 밉니다
- `LRC 내보내기` — `.lrc` 파일로 내려받습니다
- `저장` — Supabase 의 `lyrics` 에 곡과 묶어 저장합니다. **이 버튼은 7단계에서 추가합니다.** 6-C 에서는 내보내기까지만 만들고, 만든 큐는 `.lrc` 로 내려받아 두었다가 다시 올려 씁니다

#### `가사 저장` 이 담는 것

**가사 큐만 담습니다.** 줄과 타임스탬프가 곡에 묶여 올라가고, 시각 미정 줄도 그대로 갑니다. 씬·슬라이더·관객 영향력·팔레트는 **담기지 않습니다** — 그쪽은 12 프리셋의 `프리셋 저장` 몫입니다. 음원 파일도 올라가지 않습니다 (F-700).

버튼 이름을 둘 다 `저장` 으로 두었더니 검수에서 하나만 누르고 둘 다 저장된 줄 아는 일이 있었습니다. `가사 저장` 과 `프리셋 저장` 으로 갈라 적고, 각 패널이 무엇을 안 담는지 한 줄로 알립니다.

#### 원문 영역과 큐

**원문 영역은 지금 큐를 비춥니다.** 둘이 따로 놀면 불러온 가사 아래에 한 줄을 적고 `파싱` 을 눌렀을 때 스무 줄이 그 한 줄로 바뀝니다. 리허설에서 실제로 벌어지는 일은 "가사 파일은 있는데 한 줄이 틀렸다" 이지 "처음부터 만든다" 가 아닙니다.

원문을 사람이 고쳐 큐와 어긋나면 **손댄 상태**가 되고, `파싱` 옆에 `미반영` 이 붙습니다. 손댄 상태에서 큐가 바뀌면 계기마다 다르게 다룹니다.

| 큐가 바뀐 계기 | 손댄 상태일 때 |
|---|---|
| **파일 로드** | **갈아 끼웁니다.** 손댄 글을 버리고 새 파일 원문으로 채운 뒤 손댄 상태를 풉니다 |
| 탭 모드로 시각 찍기 | 다시 그리지 않습니다 |
| 줄 목록에서 고치거나 지우기 | 다시 그리지 않습니다 |

손대지 않은 상태에서는 어느 계기든 큐를 그대로 따라갑니다.

**파일 로드만 예외인 이유가 있습니다.** 파일을 여는 것은 "이 가사로 바꿔라" 라고 사용자가 직접 말한 행위입니다. 그 자리에서 원문이 갈리지 않으면 화면에 보이는 글과 실제 큐가 어긋난 채로 남고, 그다음 `파싱` 이 방금 연 파일을 지웁니다. 손댄 글을 지키고 싶으면 파일을 열기 전에 `파싱` 을 누르면 됩니다. 리허설 중에 대화상자를 띄워 묻지 않습니다.

`파싱` 은 병합하지 않습니다. 원문 영역의 내용으로 큐를 통째로 바꿉니다. 병합하면 같은 시각이 겹치고 순서가 꼬입니다.

#### 시각 미정 줄

큐의 줄은 시각이 없을 수 있습니다 (`t: null`). 시각이 안 붙은 줄을 파싱에서 버리면 `길이에 균등 배분` 이 나눌 대상이 이미 사라져 두 기능이 서로를 무효로 만들고, "앞부분만 찍어 두고 뒤는 아직" 이라는 흔한 상태를 다룰 수 없습니다.

| 자리 | 시각 미정 줄을 |
|---|---|
| 줄 목록 | 시각 칸에 `--:--.--` 를 흐리게 둡니다 |
| `길이에 균등 배분` | **이것만 대상으로 합니다** |
| 탭 모드 | 이것부터 순서대로 찍습니다 |
| 재생 (표시 탭 · 가사 씬 · 합성 씬) | 건너뜁니다 |
| `LRC 내보내기` | 뺍니다. 몇 줄을 뺐는지 알립니다 |
| 03 패널 머리의 `n / 총` | 세지 않습니다 |

머리의 총 줄 수는 **재생에 쓰이는 줄만** 셉니다. 줄 목록의 행 번호를 쓰면 미정 줄이 섞여 있을 때 재생 중에 번호가 건너뛰고 끝내 총 줄 수에 닿지 못합니다.

#### 클릭 한 번에 두 가지 일을 걸지 않습니다

`▸` 는 탐색만, 시각 칸은 시각 수정만, 가사 칸은 글자 수정만 합니다. 재생 중에 가사를 고치려다 재생 위치가 튀면 리허설에서 쓸 수 없습니다.

명세는 「타임스탬프를 누르면 탐색」 이라고 적고 있지만, 그러면 시각을 고칠 자리가 없어집니다. 탐색을 `▸` 로 따로 빼서 세 칸이 각각 하나씩 맡게 했습니다.

#### 시각은 1/100초에 맞춰 둡니다

LRC 가 담을 수 있는 최소 단위가 `[mm:ss.xx]`, 곧 1/100초입니다. 탭으로 찍은 시각은 그보다 잘게 나오므로, 만드는 순간 1/100초로 맞춥니다. 맞추지 않으면 화면에 `03.10` 으로 적힌 줄이 파일에는 `03.11` 로 나가고, 그 파일을 다시 읽으면 줄마다 1/100초씩 움직인 것처럼 보입니다.

같은 이유로 **줄 목록의 시각 칸과 내보내기가 같은 함수를 씁니다.** 트랜스포트의 시계(`formatTime`)는 남은 자리를 버리지만 — 아직 닿지 않은 시각을 먼저 띄우면 안 되므로 — 타임스탬프는 반올림해야 파일과 맞습니다.

#### `길이에 균등 배분` 이 나누는 방식

미정 줄이 이어지는 구간마다 앞뒤의 확정된 줄을 기둥으로 삼아 그 사이를 고르게 나눕니다. 앞에 기둥이 없으면 0초, 뒤에 없으면 곡 끝을 씁니다. 맨 앞 구간만 0초를 포함합니다 — 전부 미정일 때 첫 줄이 0초에서 시작하도록.

버튼 하나로 두 경우가 다 풀립니다. 처음부터 만들 때는 모든 줄이 미정이라 전부 배분되고, 앞부분만 찍어 둔 상태에서는 빈자리만 채웁니다.

#### 찍는 중에는 줄을 다시 세우지 않습니다

뒤로 탐색하며 찍으면 시각 순서가 어긋날 수 있습니다. 그래도 찍는 도중에는 정렬하지 않고, 탭 모드에서 나올 때 한 번 세웁니다. 손 밑에서 줄이 자리를 바꾸면 다음에 무엇을 찍는지 놓칩니다.

### 04 관객 입력

**이 패널이 프로젝트의 정체성을 드러내는 자리이므로 신경 써서 설계합니다.**

- 입력 방식 선택: `카메라` / `마이크` / `시뮬` / `끔` 네 개 버튼
- 미리보기 영역: 카메라 방식이면 64×36 격자 시각화, 마이크 방식이면 대역 막대
- 큰 숫자로 현재 관객 에너지(0.00~1.00)와 상태 이름
  - 상태: `잠잠함` / `술렁임` / `활발함` / `폭발`
- 24칸 LED 막대로 에너지를 시각화합니다
- 보정 상태: `보정 중 42%` 또는 `보정 완료`. 옆에 `재보정` 버튼
- **관객 영향력 슬라이더 (0~100%)** — 이 값이 연출에 얼마나 섞일지를 정합니다. 기본 60%
- 하단 고정 문구: `NO FRAMES STORED — 영상은 저장되지도 전송되지도 않습니다`

### 05 팔레트

**색을 다루는 자리입니다.** 원본 프로토타입은 톤 세 가지 중 하나를 고르는 방식이었는데, 여기서는 색 다섯 개를 묶은 팔레트를 고르거나 직접 만듭니다. 규칙은 `05-signal-processing.md` 8절에 있습니다.

#### 자동 스위치

- `자동` 을 켜면 곡의 분위기가 팔레트를 고릅니다. 밝고 신나는 곡은 노랑 계열, 차분하고 어두운 곡은 파랑 계열로 갑니다
- 자동일 때 지금 무엇이 섞이고 있는지를 글자로 보여 줍니다. `침잠 62% + 평온 38%` 형태입니다. 색이 왜 이렇게 나왔는지 오퍼레이터가 납득할 수 있어야 합니다
- **자동과 수동은 둘 중 하나입니다.** 섞지 않습니다 (8-5절)
- **자동이 켜져 있으면 어느 카드에도 선택 표시가 없습니다.** 지금 나가는 색은 카드 하나가 아니라 둘의 혼합이고, 그것은 섞임 표시가 말해 줍니다
- **카드를 누르면 자동이 꺼지고 그 카드가 선택됩니다.** 카드를 누른다는 것 자체가 "내가 색을 정하겠다"는 의사입니다. 탭 템포(F-303-2)와 같은 원칙입니다
- `자동` 을 토글로 끄면 직전 섞임에서 우세했던 팔레트가 선택됩니다. 색이 크게 튀지 않습니다
- `전환 시간` 슬라이더 (0.5~8초, 기본 2.5초) — 색이 바뀔 때 걸리는 시간입니다. 짧게 두면 조명 사고처럼 보입니다

#### 분위기 평면

가로축 `밝기(valence)`, 세로축 `격렬함(arousal)` 의 정사각형 위젯입니다.

- 지금 곡의 위치를 청록색 점으로 찍고, 최근 30초의 자취를 옅게 남깁니다
- 팔레트마다 앵커를 색 점으로 찍습니다. **앵커는 끌어서 옮길 수 있습니다.** 앵커를 옮기면 그 팔레트가 어떤 곡에서 뽑힐지 바뀝니다
- 현재 점과 가장 가까운 두 앵커를 선으로 잇고, 선 위에 섞이는 비율을 적습니다

이 위젯 하나로 "지금 왜 이 색인가"가 설명됩니다. 숫자만 나열하면 리허설에서 조정할 수가 없습니다.

#### 팔레트 목록

- 카드로 나열합니다. 카드마다 이름, 컬러칩 다섯 개, `자동 후보` 토글이 있습니다. 기본 자동 후보는 네 모서리뿐이고 `MONO` 를 포함한 나머지 넷은 꺼진 상태로 시작합니다
- 기본 제공 여덟 개는 지울 수 없고, 고치면 사본이 만들어집니다
- 카드를 한 번 누르면 선택(자동을 끕니다), 두 번 누르면 편집기가 열립니다
- `새로 만들기` `복제` `삭제`

#### 컬러칩 편집기

- 역할 다섯 개(`배경` `깊이` `기본` `강조` `순간`)를 세로로 놓고, 각 줄에 컬러칩과 HEX 입력 칸을 둡니다
- 컬러칩을 누르면 색상환과 밝기·채도 슬라이더가 열립니다
- **역할마다 무엇에 쓰이는지 한 줄로 적습니다.** `순간 — 비트가 올 때만 잠깐 나타납니다` 처럼요. 이름만 보고는 어디에 칠해지는지 알 수 없습니다
- 편집하는 동안 무대 미리보기에 바로 반영합니다. 저장 버튼을 누를 때까지 기다리게 하지 않습니다. 다만 전환 시상수(8-4절)는 편집 중에도 지킵니다. 2.5초에서도 첫 0.25초에 11% 가 움직이므로 즉시 반응하는 것으로 보입니다
- 최근에 쓴 색 여덟 개를 아래에 스와치로 남깁니다

### 06 씬

**용도가 같은 것끼리 묶어 두 줄로 배열합니다.** 섞어 놓으면 공연 중에 진단용 씬을 관객에게 띄우는 사고가 납니다.

```
무대용
 [ 무대 ]   [ 합성 ]   [ 가사 ]
  공연 본편   무대+가사   가사 크게

진단용
 [ 직조 ]  [ 스펙트럼 ]  [ 관객 ]
  분석 확인    주파수     관객 신호
```

- 묶음 머리말이 `무대용` / `진단용` 을 말하므로, 버튼 아래에는 **그 씬이 무엇을 보여 주는지 한 줄**을 적습니다
- 설명은 네 글자에서 여섯 글자로 짧게 씁니다. 버튼 폭이 좁습니다
- 숫자키는 배열 순서 그대로 `1`~`6` 입니다. 머리말에 `1–6` 을 표기합니다

**`1` 이 무대인 것은 의도한 것입니다.** 공연 중에 손이 가장 자주 가는 자리이고, 급할 때 누르면 무대로 돌아옵니다.

아직 만들지 않은 씬은 버튼 아래에 어느 단계에서 오는지 적어 둡니다 (`가사는 6단계-B`).

### 07 씬 파라미터

지금 선택된 씬의 조절 값만 보여 줍니다. 씬을 바꾸면 목록이 통째로 바뀝니다.

#### 모든 씬 공통

| 슬라이더 | 범위 | 기본 |
|---|---|---|
| `강도` | 0~2 | 1.00 |
| `잔상` | 0~0.95 | 0.62 |
| `그레인` | 0~1 | 0.22 |
| `교란` | 0~1 | 0.18 |
| `몽환도 고정` | 끔 / 0~1 | 끔 |

`몽환도 고정` 은 리허설에서 "이 곡은 판정보다 더 몽환적으로 가자" 고 정할 때 씁니다. 켜면 자동 판정을 무시하고 이 값을 씁니다. 프리셋에 저장됩니다.

**공통입니다.** 씬 파라미터가 아니라 연출 파라미터(F-405)이지만 손이 가는 자리가 여기라 07 패널에 둡니다. 이 값이 무대 씬의 결만이 아니라 무대·합성·가사 씬의 교란까지 정하므로, 무대 씬을 골랐을 때만 보이면 가사 씬에서 손댈 방법이 없습니다.

#### 직조 씬을 골랐을 때

원본 프로토타입에 있던 조절 값입니다. 리허설에서 곡마다 결을 맞추는 데 씁니다.

| 슬라이더 | 범위 | 기본 | 뜻 |
|---|---|---|---|
| `경사(세로실)` | 16~96 | 48 | 세로실 개수 |
| `위사(가로실)` | 10~60 | 30 | 화면에 남기는 행 수 |
| `장력` | 0~1 | 0.52 | 실이 흔들리는 폭 |
| `직조 속도` | 1~4 | 2 | 비트당 쌓는 줄 수 |
| `스템 분리` | 켬/끔 | 켬 | 세로실에 스템 네 종류를 순환 배치 |

**`경사`(세로실 개수)만 새로 쌓이는 행부터 적용합니다.** 행마다 `warp` 를 들고 있으므로 소급해서 다시 계산하면 천이 한 번에 뒤틀립니다.

**`장력` 은 매 프레임 전역으로 적용됩니다.** 이 값은 교차점 위치를 계산할 때마다 들어가고, `expansion` 이 이미 매 프레임 전체를 흔들고 있습니다. 행마다 고정하면 관객 반영과 어긋납니다.

#### 무대 씬을 골랐을 때

| 슬라이더 | 범위 | 기본 | 뜻 |
|---|---|---|---|
| `입자 수 상한` | 800~8000 | 6000 | 프레임이 모자라면 이것부터 내립니다 |
| `유체 워핑` | 0~2 | 1.0 | 배경이 휘는 정도의 배율 |
| `블룸 반경` | 0~2 | 1.0 | 빛 번짐의 배율 |
| `블룸 세기` | 0~2 | 1.0 | |

#### 공통 규칙

- 모든 슬라이더 오른쪽에 `자동` 버튼을 둡니다. 누르면 기본값이나 자동 산출값으로 되돌아갑니다
- 자동에서 벗어난 슬라이더는 손잡이를 청록색으로 칠해, 어느 것을 손댔는지 한눈에 보이게 합니다
- 모든 값이 프리셋에 저장됩니다 (`06-data-model.md` 의 `scene_params`)

### 08 연출 파라미터

연출 번역 엔진이 만든 값을 슬라이더와 막대로 함께 보여 줍니다. 사용자가 밀면 수동 보정값이 되고, 자물쇠를 풀면 다시 자동으로 돌아갑니다.

- `밀도` `크기` `속도` `밝기` `확산` `교란` `몽환도`
- 각 막대는 두 층으로 그립니다. 아래층은 음악만으로 나온 값(흰색), 위층은 관객이 더해진 최종값(청록색)입니다. **두 층의 차이가 곧 관객의 기여분입니다**
- `몽환도` 만 두 층의 방향이 반대입니다. 관객이 뜨거울수록 값이 내려가므로 청록색 층이 흰색 층보다 짧습니다. 이 항목에는 막대 옆에 아래쪽 화살표를 붙여 방향이 다르다는 것을 알립니다
- 패널 머리말에 현재 분위기를 적습니다. `침잠 · 밝기 0.24 · 격렬함 0.19` 형태입니다
- 색은 이 패널이 아니라 05 팔레트 패널에서 다룹니다. 색은 값 하나가 아니라 다섯 개의 묶음이라 막대로 표현할 수 없습니다

### 09 분석 리드아웃

수치를 표로 나열합니다. 진단용이므로 빽빽해도 됩니다.

- BPM, 신뢰도, 마디, 박, 위상
- RMS, 피크, 플럭스, 센트로이드
- 6밴드: SUB / LOW / LMID / MID / HI / AIR
- 스템 4종
- 관객 에너지, 보정률
- 프레임 속도

#### BPM 표시 문턱

| 신뢰도 | 상단 바 | 09 리드아웃 |
|---|---|---|
| ≥ 0.45 | 또렷하게 | 숫자 |
| 0.20 ~ 0.45 | 흐리게 | 숫자 |
| < 0.20 | `---` | `---` |

**마디·박이 비어 있는데 BPM 만 숫자로 떠 있으면 안 됩니다.** 조용한 방을 마이크로 받으면 마디와 박은 `—` 로 비는데(템포 추적기의 무음 게이트, `05-signal-processing.md` 3-4절) BPM 은 마지막 값을 유지하도록 되어 있어 109·113 같은 숫자가 남습니다. 읽는 사람은 그것을 아직 유효한 값으로 봅니다.

문턱 0.20 의 근거입니다. 조건별로 신뢰도를 쟀습니다 (표본 80ms · 조건당 14초).

| 조건 | 신뢰도 최소 / 중앙 / 최대 |
|---|---|
| 조용한 방 — 조용한 홀 (마이크) | 0.070 / 0.080 / 0.100 |
| 조용한 방 — 공조가 도는 홀 (마이크) | 0.060 / 0.110 / 0.120 |
| 아주 작게 튼 음악 (마이크) | 0.750 / 0.780 / 0.780 |
| 정상 볼륨 음악 (마이크) | 0.770 / 0.790 / 0.790 |
| 데모 신스 | 0.640 / 0.740 / 0.750 |
| 발라드 도입부 (파일, 피아노만) | 0.000 / 0.010 / 0.020 |
| 발라드 정상 (파일) | 0.010 / 0.080 / 0.300 |

잡음(≤0.12)과 타악이 있는 음악(≥0.64) 사이가 넓어서 그 안이면 어디에 두어도 같게 동작합니다. 0.20 은 잡음 위로 여유를 두면서 0.20~0.45 의 「흐리게」 구간을 남기는 자리입니다.

**타악이 성긴 곡에서는 BPM 이 `---` 로 뜹니다.** 위 표의 발라드가 그렇습니다. 신뢰도가 잡음과 같은 수준이라 어떤 문턱으로도 갈리지 않습니다. 추정값 자체는 맞았지만(72.6 / 실제 72), 추정기가 근거를 대지 못하는 값을 콘솔이 단정해서는 안 됩니다. 이때의 처방은 문턱이 아니라 `TAP` 과 `BPM 잠금` 입니다. 잠금 중에는 이 규칙을 적용하지 않습니다 (F-303-2).

**BPM 이 `---` 인 동안 09 리드아웃은 사유를 한 줄 같이 띄웁니다.** 공연 중에 숫자가 사라지면 고장인지 설계인지 알 수 없습니다. 사유와 다음 손동작을 같이 놓습니다. 상단 바는 자리가 좁아 두지 않습니다.

사유는 세 갈래입니다. 아래로 갈수록 좁은 조건이고, 먼저 맞는 것을 씁니다.

| 조건 | 문구 |
|---|---|
| 소스가 없다 | `입력 없음 · 마이크나 파일을 연결하십시오` |
| `rmsSlow` 가 오래 `STEM_GATE` 아래 (아래 「기다리는 시간」) | `입력이 너무 작습니다 · 볼륨과 마이크 모드를 확인하십시오` |
| 소리는 들어오는데 신뢰도만 낮다 | `BPM 신뢰도 낮음 · TAP 으로 잡으십시오` |

**앞의 두 문구에서는 `TAP` 을 강조하지 않습니다.** 입력이 없는 상황의 처방은 탭이 아니라 연결입니다. 세 번째에서만 `TAP` 을 밝게 씁니다.

마이크가 붙지 않은 상태와 조용한 방이 화면에서 구별되어야 합니다. 셋을 한 문구로 묶으면 앞의 둘은 사실이 아닌 말을 하게 됩니다.

#### 「입력이 작다」의 기준

문턱은 스템 게이트와 **같은 `STEM_GATE`(0.015)** 를 씁니다 (`05-signal-processing.md` 4절). 「들어오는 소리가 음악인가 암소음인가」라는 같은 물음에 두 개의 숫자를 두지 않습니다.

#### 기다리는 시간은 두 단입니다

| 이 소스에서 소리를 들은 적 | 기다리는 시간 | 왜 |
|---|---|---|
| 없다 | **2.0초** | 마이크 모드·볼륨 설정 실수는 빨리 알려야 합니다 |
| 있다 | **30.0초** | 공연에서 곡과 곡 사이는 늘 2초를 넘습니다 |

소스를 바꾸면 처음부터 셉니다. 파일이 잘 나오다가 마이크로 옮겼는데 모드가 틀렸다면, 그것이야말로 2.0초 안에 알려야 하는 상황입니다.

**첫 단 2.0초** — `rmsSlow` 가 문턱 아래로 **연속해서** 머무는 시간입니다.

| 조건 | 가장 긴 구간 | 전체 비율 |
|---|---|---|
| 조용한 방 — 조용한 홀 | 13.42초 | 100% |
| 조용한 방 — 공조가 도는 홀 | 9.62초 | 93% |
| 발라드 도입부 (피아노만) | **0.94초** | 25% |
| 발라드 중간 | 0.82초 | 14% |
| 아주 작게 튼 음악 | 0.28초 | 20% |
| 정상 볼륨 음악 · 발라드 정상 | — | 0% |

실제 음악은 아무리 조용해도 0.94초를 넘기지 않고, 조용한 방은 잰 구간 내내 아래에 있습니다. 2.0초는 양쪽에 두 배 넘는 여유를 둔 자리이고, 템포 추적기의 무음 게이트(`SILENCE_HOLD`)와도 같은 값입니다.

**둘째 단 30.0초** — 곡 셋을 이어 붙인 82초짜리 셋리스트를 마이크로 받아 쟀습니다. 곡 사이에 박수·환담·완전한 정적을 차례로 넣었고, 전체에 방 암소음을 깔았습니다.

| 구간 | `rmsSlow` 최소 / 중앙 / 최대 | 문턱 아래 비율 |
|---|---|---|
| 1곡 (120 BPM) | 0.110 / 0.230 / 0.367 | 0% |
| 박수 | 0.073 / 0.131 / 0.274 | **0%** |
| 환담 (멘트) | 0.019 / 0.078 / 0.313 | **0%** |
| 2곡 (96 BPM) | 0.010 / 0.164 / 0.356 | 5% |
| 박수 | 0.022 / 0.122 / 0.235 | **0%** |
| 완전한 정적 (방 암소음만) | 0.010 / 0.012 / 0.299 | 93% |
| 3곡 (132 BPM) | 0.014 / 0.233 / 0.376 | 1% |

**박수와 환담은 문턱을 한 번도 내려가지 않습니다.** 객석 마이크가 있는 한, 공연에서 곡과 곡 사이는 「조용한 입력」이 아닙니다. 걸리는 것은 진짜 아무 소리도 없을 때뿐이고, 그 구간에서 문턱 아래로 이어진 시간이 **20.37초** 였습니다.

30.0초는 그 위로 1.5배 여유를 둔 값입니다. 케이블이 빠지면 30초 안에 뜹니다.

정적이 30초를 넘는 긴 멘트나 세트 교체에서는 이 줄이 뜹니다. BPM 이 이미 `---` 인 동안에만 보이는 줄이므로 연출에는 영향이 없습니다.

**파일을 세워 둔 동안에는 이 줄을 띄우지 않습니다.** 정지·일시정지 중에는 누적 시간도 세지 않습니다. 왜 조용한지를 코드가 이미 알고 있으므로 값으로 덮을 일이 아닙니다. 마이크·라인은 정지와 무음이 구별되지 않지만 파일은 구별됩니다. 재생 중인데 조용한 것이면 위의 두 단을 그대로 따릅니다.

#### 문턱을 오갈 때 표시가 뒤집히지 않습니다

신뢰도가 문턱 근처에 머무는 곡이면 표시가 「흐린 숫자 ↔ `---`」로 깜빡일 수 있습니다. 발라드 파일에서 30초씩 재 봤습니다 (표본 50ms · 578표본).

| 구간 | 신뢰도 최소 / 중앙 / 최대 | `---` 였던 비율 | 뒤집힘 |
|---|---|---|---|
| 처음부터 30초 | 0.00 / 0.03 / 0.49 | 92% | **1회** (27.6초) |
| 14초 이후 30초 | 0.00 / 0.33 / 0.68 | 48% | **1회** (14.3초) |

둘 다 한 방향으로 한 번 넘어가고 되돌아오지 않습니다. 문턱을 지나는 자리를 50ms 간격으로 들여다봐도 `0.13 → 0.14 → 0.11 → 0.13 → 0.20 → 0.26 → 0.33` 으로 단조롭게 오릅니다. 신뢰도가 이미 평활을 거친 값(계수 0.3)이고 리드아웃이 4프레임마다 한 번 갱신되기 때문입니다. **히스테리시스를 넣지 않았습니다.** 넣게 된다면 켜짐 0.20 / 꺼짐 0.17 자리입니다.

잡음에서 추정기가 도는 것 자체는 별개 과제입니다 (`issues/10-tempo-accuracy.md`, GitHub #11).

값이 0.8 을 넘으면 그 칸을 강조합니다.

### 10 외부 연동

원본 프로토타입의 「08 · TouchDesigner 라우팅」 패널을 옮긴 자리입니다 (F-800). 8단계에서 만듭니다.

- 주소 입력 칸. 기본값 `ws://localhost:9980`
- `연결` / `해제` 버튼, 형식 전환 버튼(JSON ↔ OSC-TXT)
- 상태 표시: `OFFLINE` · `CONNECTING` · `LIVE`. 옆에 램프를 둡니다
- `송출 레이트` 슬라이더. 5~120, 기본 60
- 송출 채널 표: 채널명과 현재 값. 묶음별로 접었다 펼 수 있게 합니다. 채널이 오십 개가 넘어 한 번에 펴 두면 레일을 다 먹습니다
- 안내: `TouchDesigner 쪽은 WebSocket DAT(포트 9980) → JSON DAT → CHOP Execute 순으로 구성합니다.`
- 경고: `배포된 주소(https)에서는 보안 정책상 로컬 소켓 연결이 차단됩니다. 외부 연동은 로컬 실행에서 사용하세요.`
- 연동 스크립트 복사 버튼

**연결이 끊기면 자동으로 다시 붙습니다.** 그동안 상태는 `CONNECTING` 이고, 몇 번째 시도인지를 상태 옆에 작게 답니다. `해제` 를 눌러 끊은 경우에는 다시 붙지 않습니다. 사람이 끊은 것과 상대가 죽은 것을 화면이 구분해야 합니다.

**채널 표는 값이 바뀌는 것을 보여 주되 매 프레임 다시 그리지 않습니다.** 초당 네 번이면 눈으로 확인하기에 충분하고, 송출 자체와는 무관합니다. 표를 그리느라 프레임을 잃지 마십시오.

**연결하지 않아도 콘솔은 그대로 돕니다.** 이 패널은 무대 밖으로 값을 보내는 통로일 뿐이라, 연결 실패가 렌더 루프나 분석 루프를 건드리면 안 됩니다.

**저장은 언제나 먼저 로컬에 남습니다.** 로그인하지 않았거나 인터넷이 끊겼어도 새로 고침한 뒤 불러오면 같은 상태가 됩니다. 연결이 돌아오면 그때 올라갑니다. 공연장에서 인터넷이 끊기는 것은 흔한 일이고, 그때 프리셋을 못 부르면 리허설에서 맞춰 둔 값이 통째로 날아갑니다.

**제안을 자동으로 적용하지 않는 이유**가 있습니다. 리허설 중에 곡을 다시 열면 손봐 둔 값이 그 순간 사라집니다. 적용 순서도 F-703 그대로입니다.

```
loadFile  →  프리셋 제안  →  applyPreset
```

파일 로드가 템포 잠금을 푸는 동작이라, 프리셋을 먼저 걸면 `lockedBpm` 과 `tempoLocked` 가 곧바로 지워집니다.

씬마다 어느 화면을 위한 것인지 먼저 밝힙니다. 이것을 구분하지 않으면 오퍼레이터가 볼 그림과 관객이 볼 그림이 뒤섞입니다.

| 키 | 씬 | 용도 | 버튼 아래 한 줄 | 무엇을 위한 화면인가 |
|---|---|---|---|---|
| 1 | **무대 BLOOM** | **무대** | 공연 본편 | **공연 본편에 거는 화면입니다** |
| 2 | 합성 COMPOSITE | 무대 | 무대+가사 | 바탕 위에 가사를 얹습니다 |
| 3 | 가사 TYPE | 무대 | 가사 크게 | 가사를 큰 활자로 |
| 4 | 직조 WEAVE | 진단 | 분석 확인 | 분석이 제대로 도는지 곡의 진행을 직물로 남겨 봅니다 |
| 5 | 스펙트럼 SPECTRUM | 진단 | 주파수 | 주파수와 6밴드 |
| 6 | 관객 FACES | 진단 | 관객 신호 | 관객 신호가 들어오는지 확인합니다 |

### 직조 (WEAVE)

**곡이 흐르는 동안 천이 짜입니다.** 가로실과 세로실이 교차하며, 음악이 센 구간은 넓은 띠로, 약한 구간은 촘촘한 결로 남습니다. 이름 그대로 두 방향 실의 교차가 핵심이므로, 가로줄만 쌓이면 이 씬이 성립하지 않습니다.

#### 격자 파라미터

| 값 | 기본 | 뜻 |
|---|---|---|
| `warp` | 48 | 세로실 개수 |
| `weft` | 30 | 가로실 최대 개수. 넘으면 오래된 것부터 버립니다 |
| `tension` | 0.52 | 실이 흔들리는 폭 |
| `rate` | 2 | 비트당 몇 줄을 쌓을지 |
| `split` | true | 세로실에 스템 네 종류를 `i % 4` 로 순환 배치 |

여백은 가로 5.5%, 세로 7.5% 입니다.

#### 한 줄이 쌓이는 시점

`floor((beat + phase) × rate)` 가 바뀔 때마다 한 줄을 쌓습니다. 각 줄은 그 순간의 스템 네 값, RMS, 센트로이드, 마디·박 번호, 시각, 가사 인덱스를 함께 담습니다.

#### 행 높이는 세기에 비례합니다

균등 간격이 아닙니다. 센 구간이 천에서 넓게 남아야 곡의 강약이 보입니다.

```
row.lv  = max(stems[0..3])          // 행을 쌓을 때 함께 저장합니다
wsum[k] = 0.55 + row.lv × 1.15
행 위치  = 아래에서부터 wsum 의 누적 비율만큼 올라간 자리
```

`row.lv` 는 행을 쌓는 시점에 네 스템의 최댓값을 계산해 함께 담아 두는 값입니다. 그리는 시점에 다시 구하지 않습니다.

#### 두 가지 레벨을 구분합니다

이름이 비슷해 헷갈리기 쉬우므로 먼저 정리합니다. **둘은 다른 값이고 쓰이는 자리가 다릅니다.**

| 이름 | 정의 | 쓰이는 곳 |
|---|---|---|
| `lvl` | `row.s[g]` — 그 행의 **해당 스템값** 하나 | 교차점 가로 흔들림 |
| `lv` | `clamp(row.lv × 0.8 + row.rms × 0.5 + 0.16, 0, 1)` | 가로실 굵기, 가로실 세로 흔들림, 가로실 색 밝기, 덧실 |

`lv` 는 단순한 RMS 가 아닙니다. **최대 스템값과 RMS 를 섞고 바닥값 0.16 을 더한 합성값**입니다.

- 바닥값 0.16 이 없으면 조용한 구간에서 가로실이 거의 사라져 천이 끊긴 것처럼 보입니다
- 최대 스템값 항이 없으면 드럼만 세게 나오는 구간에서 실이 굵어지지 않습니다

#### 교차점이 흔들립니다

실이 직선이면 천이 아니라 격자표가 됩니다. 각 교차점의 가로 좌표를 사인파 두 개로 흔듭니다.

```
ph = time × (1.1 + g × 0.23) + i × 0.55 + k × 0.31
d  = sin(ph) × lvl
   + sin(ph × 1.7 + 1.2) × lvl × 0.42
   + sin(time × 3.1 + i × 0.9) × liveLvl × 0.45
x  = padX + i × cw + clamp(d, -1.5, 1.5) × (tension × intensity) × cw × 0.52
```

`g` 는 스템 인덱스, `i` 는 세로실 번호, `k` 는 행 번호입니다. `liveLvl` 은 최근 세 행에만 적용하는 현재 스템값으로, 방금 짜인 부분이 아직 살아 움직이게 합니다.

가로실은 세로로도 흔듭니다.
```
y = 행 위치 + sin(i × 0.42 + row.t × 2.0) × ch × 0.20 × lv
```

#### 그리는 순서

순서를 지켜야 겹침이 자연스럽습니다.

1. **가로실(위사)** — 행마다 `warp` 개 점을 이어 선으로 그립니다
   - 굵기 `clamp(0.55 + lv × 1.7, 0.5, 2.6)`, 가장 최근 행(`k === 0`)만 `× (1.5 + flash)`
   - 색 `toneCol(1, lv × age, hot)`. **색 인덱스는 1(베이스) 고정입니다.** 스템별로 갈리지 않습니다
   - `age = 0.35 + 0.65 × (1 − k/n)` 로 오래된 행이 흐려집니다
   - `hot = (row.s[0] > 0.78) && (k < 2)` — 드럼이 세게 난 최근 두 행만 강조색입니다
2. **세로실(경사)** — 세로실마다 모든 행을 이어 그립니다
   - `mlv = clamp(누적합 / n × 1.3, 0, 1)`, `v = (mlv × 0.5 + 현재 스템값 × 0.5)^1.45`
   - 굵기 `clamp((0.34 + v² × 1.9) × WGT[g], 0.35, 3.0)`
   - 색 `toneCol(g, v, 현재 스템값 > 0.86 && g === 0)`. 여기는 스템별로 갈립니다
3. **매듭** — 스템값이 0.58 을 넘은 자리에 사각 표식을 찍습니다
   - `kn = (값 − 0.58) / 0.42`, 크기 `(1.6 + kn × 3.4) × (k < 3 ? 1.25 : 1)`
   - **그 스템이 배치된 세로실에만 찍습니다.** `split` 이면 `i = g` 부터 4칸 간격, 아니면 `i = 0` 부터 3칸 간격
   - 드럼(`g === 0`)이거나 `kn > 0.72` 이면 `rgba(255, 42, 0, 0.30 + kn × 0.62)`, 아니면 `toneCol(g, 0.45 + kn × 0.55, false)`
4. **평직 교차** — 가로실이 위로 올라오는 지점에 짧은 덧실을 찍습니다
   - 길이 `cw × 0.62`, 두께는 그 행의 가로실 굵기와 같게
   - 행마다 한 칸씩 어긋나게(`i = k % 2` 부터 2칸 간격)
   - 색 `toneCol(1, lv × age, false)`. **여기도 색 인덱스는 1 고정입니다**
5. **셀비지(마디 번호)** — `rate × 4` 행마다 왼쪽 여백에 마디 번호 세 자리, 오른쪽 여백에 시각을 9px 고정폭으로 적습니다. 색 `rgba(110, 107, 100, 0.85 − k/n × 0.6)`
6. **직구 빔 라인** — 화면 아래쪽 `SH − padY + ch × 0.55` 위치에 가로선 하나. `flash > 0.2` 이면 강조색, 아니면 `rgba(232, 228, 220, 0.35)`. 지금 실이 짜이고 있는 자리를 표시합니다

`flash` 는 **비트가 올 때 1 로 세우고 `dt × 3.4` 로 감쇠시키는 값**입니다. 약 0.29초에 0 이 됩니다. 온셋이 아니라 비트입니다. 온셋으로 하면 최근 행이 거의 항상 굵어져 강조의 뜻이 없어집니다.

#### 스템별 실 굵기

```
WGT = [1.10, 1.55, 0.80, 0.58]   // drums, bass, vocal, other
```
베이스가 가장 굵고 기타 성분이 가장 가늡니다.

#### 색

원본은 `toneCol(g, v, hot)` 한 함수로 색을 냈고 모드가 `mono` · `alert` · `duo` 셋뿐이었습니다. 이번 확장에서는 그 세 모드를 팔레트 세 개로 흡수하고, 함수는 팔레트의 역할 색을 읽도록 일반화합니다.

```
toneCol(g, v, hot) =
  hot  이면        pal.hot
  g == 2 (보컬)    pal.accent
  g == 3 (기타)    pal.deep 과 pal.base 를 0.5 로 섞은 색
  그 외            pal.base
투명도는 원본 그대로 0.10 + v × 0.90
```

원본의 세 모드는 다음 팔레트에 대응합니다. 기존 화면을 그대로 보고 싶으면 이 셋 중 하나를 고르면 됩니다.

| 원본 모드 | 대응 팔레트 |
|---|---|
| `mono` | `MONO` |
| `alert` | `격정 FERVENT` |
| `duo` | `평온 SERENE` |

**직조 씬은 팔레트를 바꿔도 여전히 미니멀합니다.** 이 씬은 화려한 무대 영상이 아니라 데이터를 직물로 은유한 아트워크이고, 그것이 이 씬의 자리입니다. 무대에 걸 화면은 아래의 무대 씬입니다.

#### 관객 반영

관객 에너지는 `expansion` 을 통해 `tension` 에 곱해져 실의 흔들림 폭을 키우고, 잔상 길이에도 반영됩니다.

#### 셀비지와 빔 라인은 진단용입니다

5·6층의 마디 번호와 빔 라인은 글자와 눈금이므로 무대에 걸 그림이 아닙니다. 직조가 콘솔 진단 씬이므로 여기서는 그대로 그립니다. 합성 씬의 바탕으로 직조를 고른 경우에는 이 두 층을 빼십시오.

#### 대기 화면

행이 두 개 미만이면 빈 베틀 화면을 그립니다. 세로실만 가늘게 세워 두고 음악을 기다리는 상태를 보여 줍니다.

### 가사 (TYPE)

현재 가사를 화면 중앙에 큰 활자로 놓고, 진행률에 따라 단어를 하나씩 밝힙니다. 온셋이 오면 활자가 미세하게 흔들립니다. 관객 에너지는 활자 크기에 반영됩니다.

교란은 무대 씬과 같은 식(`glitchEff = glitch × (1 − dreaminess × 0.85)`)으로 활자에 겁니다.

### 관객 (FACES)

관객 입력을 그대로 보여 주는 씬입니다. 카메라 방식이면 64×36 격자를 밝기 타일로, 마이크 방식이면 대역별 막대의 벽으로 그립니다. 신호가 없으면 `관객 신호 없음 — 카메라를 연결하거나 시뮬을 켜세요` 를 중앙에 적습니다.

**이 씬은 진단용이고, 관객이 그림으로 화면에 나오는 유일한 자리입니다.** 신호가 실제로 들어오는지 오퍼레이터가 확인하는 용도입니다. 무대에 걸지 마십시오.

관객이 화면에 들어가는 방식은 두 갈래이고, 무게가 다릅니다.

| 방식 | 어디에 | 무엇인가 |
|---|---|---|
| **값으로** | 무대·직조·가사·합성 | **원칙입니다.** `audienceEnergy` 한 숫자가 연출 파라미터에 곱해집니다 |
| 그림으로 | 관객 씬 하나뿐 | 진단용입니다. 신호가 오는지 보는 계기판입니다 |

기존 프로토타입이 관객을 그림으로만 쓰고 값으로는 쓰지 않았던 것이 이 프로젝트가 채우려는 자리입니다 (`01-overview.md` 3절). 그림을 늘리는 방향으로 가지 마십시오.

### 스펙트럼 (SPECTRUM)

주파수 스펙트럼을 가로축에 로그 스케일로 펼치고, 6밴드 경계에 눈금을 긋습니다. 아래에는 파형을 겹칩니다.

### 합성 (COMPOSITE)

바탕 위에 가사를 얹습니다. 두 층입니다.

**바탕을 고를 수 있습니다.** 07 씬 파라미터에서 `직조` 와 `무대` 중 하나를 고릅니다. 기본은 `무대` 입니다. 원본 프로토타입의 합성 씬은 직조를 바탕으로 썼으므로, 원본과 같은 화면을 보려면 `직조` 로 바꾸면 됩니다.

가사는 팔레트의 `accent` 로 그리고, 현재 부르고 있는 단어만 `hot` 으로 밝힙니다.

**관객 격자를 겹치지 않습니다.** 관객은 이 씬에도 값으로만 들어옵니다. 바탕이 되는 무대·직조 씬이 이미 `expansion` 과 `dreaminess` 로 관객을 받고 있습니다.

객석 카메라를 무대 스크린에 띄우는 연출은 실제 공연에서 쓰이지만, 그것은 이 프로젝트의 명제가 아니라 별개의 연출 도구입니다. 필요해지면 그때 따로 설계합니다.

### 무대 (BLOOM)

**공연 본편에 거는 화면입니다.** 직조가 "무엇이 일어났는지" 를 기록하는 화면이라면, 무대는 "지금 무엇이 일어나는지" 를 느끼게 하는 화면입니다.

이 씬에는 숫자, 눈금, 라벨, 테두리를 하나도 그리지 않습니다. 관객이 보는 화면에 진단 정보가 섞이면 그 순간 무대가 아니라 계기판이 됩니다.

#### 왜 WebGL 인가

Canvas 2D 로는 빛 번짐과 수천 개의 입자를 60fps 로 그릴 수 없습니다. `shadowBlur` 로 글로우를 흉내 내면 입자 수백 개에서 이미 프레임이 무너집니다. 이 씬만 WebGL2 로 그리고, 나머지 네 씬은 Canvas 2D 를 그대로 씁니다.

라이브러리는 쓰지 않습니다. 필요한 것이 전체 화면 사각형 하나와 점 그리기뿐이라, Three.js 를 얹으면 번들만 커지고 얻는 것이 없습니다.

#### 세 층

```
층 1  배경 유체   전체 화면 사각형 + 프래그먼트 셰이더 (도메인 워핑 노이즈)
층 2  입자        gl.POINTS, 위치를 정점 셰이더에서 계산 (상태를 저장하지 않음)
층 3  블룸        밝은 부분 추출 → 1/4 해상도 블러 두 번 → 가산 합성
```

#### 층 1 — 배경 유체

노이즈를 노이즈로 한 번 더 밀어 유기적인 흐름을 만듭니다.

```glsl
vec2 q = vec2(fbm(p + t * 0.10),
              fbm(p + vec2(5.2, 1.3) + t * 0.12));
vec2 r = vec2(fbm(p + warp * q + vec2(1.7, 9.2) + t * 0.15),
              fbm(p + warp * q + vec2(8.3, 2.8) + t * 0.13));
float f = fbm(p + warp * r);
```

| 값 | 식 | 뜻 |
|---|---|---|
| `warp` | `1.2 + dreaminess × 2.6` | 몽환적일수록 크게 휘어집니다 |
| `t` | `time × (0.06 + speed × 0.10 + (1 − dreaminess) × 0.18)` | 격렬할수록 빠르게 흐릅니다 |
| fbm 옥타브 | 4 | 5 이상은 프레임만 먹고 눈에 띄지 않습니다 |

색은 팔레트에서 옵니다.

```glsl
vec3 col = mix(pal.bg, pal.deep, smoothstep(0.35, 0.75, f));
col += pal.base * pow(f, 3.0) * brightness * 0.45;
col *= 1.0 - 0.55 * pow(length(uv), 2.2);   // 비네트
```

비네트를 반드시 겁니다. 무대 스크린은 가장자리가 어두워야 화면의 경계가 관객 눈에 띄지 않습니다.

#### 층 2 — 입자

**입자의 상태를 저장하지 않습니다.** 위치를 프레임 사이에 들고 다니면 텍스처 두 장을 번갈아 쓰는 구조가 필요하고, 코드가 세 배로 늘어납니다. 대신 각 입자의 위치를 인덱스와 시각만으로 매 프레임 새로 계산합니다.

```glsl
// 인덱스에서 뽑은 고유 난수 세 개
float a = hash(i * 1.61), b = hash(i * 2.71), c = hash(i * 3.14);

float age = fract(c + time * (0.05 + speed * 0.08));
float rad = (0.12 + a * 0.75)
          * (1.0 + expansion * 0.9)
          * (0.55 + age * 0.85)
          + beatPulse * 0.18 * scale;          // 비트마다 바깥으로
float ang = b * 6.283
          + time * (0.15 + (1.0 - dreaminess) * 0.55)
          + rad * 1.8;

vec2 pos = vec2(cos(ang), sin(ang)) * rad;
pos += curl(pos * 1.7 + time * 0.08) * (0.10 + dreaminess * 0.22);
```

| 값 | 식 |
|---|---|
| 개수 | `1200 + density × 4800`, 상한은 07 패널의 `입자 수 상한` |
| 점 크기 | `(1.5 + a × 4.5) × (0.6 + scale × 1.1) × (1.0 + dreaminess × 0.8) × dpr` |
| 색 | `mix(pal.base, pal.accent, b)` 에서 `beatPulse × 0.7` 만큼 `pal.hot` 쪽으로 |
| 알파 | `(0.55 − dreaminess × 0.20) × (1 − smoothstep(0.75, 1.05, radN))` |
| 블렌딩 | 가산 (`ONE, ONE`) |

가산 블렌딩이라 입자가 겹치는 자리가 저절로 밝아집니다. 이것이 빛처럼 보이는 이유이고, 알파를 낮게 잡는 이유이기도 합니다.

#### 바깥 페이드는 확산과 함께 늘어나야 합니다

알파의 페이드 입력이 `rad` 가 아니라 **`radN`** 인 것에 유의하십시오.

```
radN = rad / (1 + expansion × 0.9)
```

`rad` 를 그대로 넣으면 **관객이 뜨거워질수록 바깥으로 밀려난 입자가 지워집니다.** 확산을 키운 만큼 페이드가 그것을 되돌리는 셈입니다.

실측이 그것을 보여 줍니다. 영향력을 0% 에서 100% 로 올렸을 때 궤도는 **+12.4%** 넓어졌는데 화면의 밝기 가중 평균 반경은 **+1.8%** 만 늘었고, p95 반경은 여덟 번 중 네 번만 올라 사실상 움직이지 않았습니다. 페이드가 바깥을 잘라 냈기 때문입니다.

궤도가 넓어진 만큼 페이드 좌표계도 함께 늘리면 잘려 나가지 않습니다. **`expansion` 은 관객이 화면에 드러나는 유일한 통로이므로, 여기서 상쇄되면 이 프로젝트의 명제가 화면에 안 보입니다.**

점 크기가 몽환도를 따라 −15% 줄어드는 것은 그대로 둡니다. 그쪽은 "퍼지고 조금 날카로워진다"의 의도된 절반입니다.

#### 확산을 재는 기준은 p95 반경입니다

**밝기 가중 평균 반경으로 재지 마십시오.** 점 크기 변화에 오염됩니다.

가운데는 입자가 몰려 가산 블렌딩으로 포화돼 있어 점이 작아져도 밝기를 유지하지만, 바깥의 성긴 입자는 작아지면 무게를 잃습니다. 그래서 몽환도가 점 크기를 줄이는 순간 **무게중심이 안쪽으로 당겨집니다.** 확산과 점 크기라는 서로 다른 두 효과가 한 숫자에 섞입니다.

우리가 재려는 것은 "입자가 바깥으로 퍼지는가"이고, 그 답은 **바깥 테두리의 위치**에 있습니다. `radN` 을 적용한 뒤 실측이 이렇습니다.

| 재는 값 | 페이드 정규화 전 | 후 |
|---|---|---|
| 밝기 가중 평균 반경 | +1.8% (8쌍 중 8쌍) | +6.3% (8쌍 중 8쌍) |
| **p95 반경** | +0.05% (8쌍 중 **4쌍**) | **+8.8% (8쌍 중 8쌍)** |

궤도가 +12.4% 넓어질 때 p95 가 +8.8% 로 거의 따라갑니다. 평균이 +6.3% 에 머무는 것은 점 크기 −15% 가 눌렀기 때문이고, 그것은 의도한 동작입니다.

**측정 편의를 위해 설계를 바꾸지 마십시오.** 평균을 +8% 까지 올리려면 점 크기의 몽환도 결합을 줄여야 하는데, 그러면 "관객이 뜨거우면 날카로워진다"가 약해집니다. 순서가 뒤바뀝니다.

`beatPulse` 는 비트가 올 때 1 로 두고 0.45초에 걸쳐 감쇠시키는 값입니다. **"비트마다 확산" 은 이 한 줄이 전부입니다.**

#### 층 3 — 블룸

빛 번짐이 없으면 색을 아무리 잘 골라도 화면이 납작합니다.

1. 밝기 추출 — `max(0, luma − 0.55)` 를 **1/4 해상도** 텍스처에 그립니다
2. 가로 블러 9탭 → 세로 블러 9탭. 반경 `(4 + dreaminess × 10) × 블룸반경배율` 픽셀
3. 원본에 가산 합성. 세기 `(0.35 + dreaminess × 0.45 + beatPulse × 0.25) × 블룸세기배율`

**1/4 해상도로 줄이는 것이 핵심입니다.** 원본 해상도에서 블러하면 프레임이 절반으로 떨어집니다. 블러는 어차피 흐려지는 것이라 해상도를 줄여도 눈에 띄지 않습니다.

#### 몽환도가 결을 바꿉니다

발라드에서는 번지고 느리게, 신나는 곡에서는 날카롭고 빠르게 나와야 합니다. 그 요구를 값 하나로 처리합니다. `dreaminess` 는 `05-signal-processing.md` 7-6절에서 옵니다.

| 자리 | `dreaminess = 1` (발라드) | `dreaminess = 0` (댄스) |
|---|---|---|
| 유체 워핑 폭 | 3.8 | 1.2 |
| 유체 흐름 속도 | 느림 | 빠름 |
| 입자 회전 속도 | 0.15 | 0.70 |
| 입자 크기 | 1.8배 | 1.0배 |
| 입자 알파 | 0.35 | 0.55 |
| 흐름 노이즈 폭 | 0.32 | 0.10 |
| 블룸 반경 | 14px | 4px |
| 블룸 세기 | 0.80 | 0.35 |
| 잔상 | 0.88 | 0.55 |
| 교란 | `glitch × 0.15` | `glitch` 그대로 |

마지막 줄이 중요합니다. **몽환적인 구간에서는 교란을 눌러야 합니다.** 발라드 도중에 화면이 찢어지면 곡과 어긋납니다.

```
glitchEff = glitch × (1 − dreaminess × 0.85)
```

**그리기 문턱은 0.12 입니다.** `glitchEff × 교란 슬라이더 × 4` 가 이 값 아래면 슬라이스를 하나도 그리지 않습니다. 그래서 몽환도가 1 에 가까우면 교란이 약해지는 것이 아니라 아예 꺼집니다 — 슬라이더가 0.2 일 때 계산하면 `glitch × 0.15 × 0.2 × 4 = 0.12 × glitch` 라 `glitch` 가 1 이어도 문턱에 닿지 않습니다. 실측에서도 몽환도 1 의 화면이 교란 0 의 화면과 구별되지 않았습니다.

**이 식은 무대 씬만의 규칙이 아니라 씬 공통입니다.** 가사 씬과 합성 씬의 활자 교란에도 같은 식을 씁니다. 활자가 찢어지는 것은 무대 화면에서 의도한 표현이고, 몽환적인 구간에서 그것이 눌리는 이유도 무대 씬과 같습니다. 이 표가 무대 씬 절 안에 있는 것은 처음 설계한 자리가 여기여서일 뿐입니다.

**갈림의 기준은 씬의 용도입니다.** 4절 표의 `무대용` 셋(무대 · 합성 · 가사)에만 이 식을 걸고, `진단용` 셋(직조 · 스펙트럼 · 관객)에는 교란을 아예 걸지 않습니다. 분석이 제대로 도는지, 관객 신호가 들어오는지 확인하는 화면입니다. 값을 읽는 화면을 어긋뜨리면 읽을 수가 없고, 무대에 걸 그림이 아니므로 연출 효과를 얹을 이유도 없습니다.

그리는 방식(Canvas 2D / WebGL)이나 합성 씬의 바탕이 무엇인지는 기준이 아닙니다. 합성 씬은 바탕이 직조여도 교란이 걸립니다.

#### 관객이 들어오는 자리

두 곳뿐입니다.

- `expansion` → 입자 반경. 객석이 뜨거워지면 입자가 바깥으로 퍼집니다
- `dreaminess` → 관객이 뜨거울수록 내려가, 화면이 날카로워집니다

색은 관객이 바꾸지 않습니다 (`05-signal-processing.md` 8-6절).

#### 대기 화면

음악이 들어오기 전에는 입자를 300개로 줄이고 거의 멈춘 상태로 천천히 떠다니게 합니다. 검은 화면을 띄우지 않습니다. 공연 시작 전에도 스크린은 켜져 있고 관객이 그것을 보고 있습니다.

#### 이 절의 수치에 대하여

**직조 씬과 달리, 이 절의 값은 실측값이 아닙니다.** 직조의 파라미터는 원본 프로토타입에서 실제로 돌던 값이지만, 무대 씬은 이번에 새로 설계한 것이라 근거가 되는 실행 기록이 없습니다.

초기값으로 쓰시되, 화면을 보고 조정한 다음 **그 값을 이 문서에 되돌려 적으십시오.** 그래야 다음 사람이 같은 화면에서 출발합니다.

### 공통 효과

- 잔상(trail): 이전 프레임을 완전히 지우지 않고 반투명하게 덮습니다
- 입자(grain): 미세한 잡음을 얹어 디지털 느낌을 줄입니다
- 교란(glitch): 온셋이나 상태 전이에서 가로 방향으로 화면을 어긋뜨립니다
- 비트 테두리: 비트마다 화면 가장자리가 짧게 번집니다

각 효과의 세기는 연출 파라미터에서 옵니다.

## 5. 반응형

콘솔은 가로 1440px 이상을 기준으로 설계합니다. 1280px 아래에서는 오른쪽 레일을 접고 아이콘 탭으로 전환합니다. 모바일은 지원하지 않습니다. 공연 콘솔이라 노트북 이상을 전제합니다.

출력 창은 어떤 비율에도 대응해야 합니다. 캔버스를 컨테이너 크기에 맞추고 `devicePixelRatio` 를 반영합니다.

## 6. 접근성

- 모든 조작 요소에 키보드 초점이 갑니다
- 색만으로 상태를 구분하지 않습니다. LED 점에는 문구를 붙입니다
- **아이콘만 있는 조작 요소를 두지 않습니다.** 공연장은 어둡고 오퍼레이터는 급하게 손을 움직입니다. 자물쇠·배수 보정처럼 그림만으로는 뜻이 통하지 않는 버튼에는 아이콘 아래에 짧은 한글 라벨을 답니다 (예: 자물쇠 아이콘 + `BPM 잠금`). 공간이 모자라면 아이콘을 줄이고 라벨을 남깁니다
- 화면 낭독기 사용자를 위해 관객 에너지와 BPM 을 `aria-live="polite"` 로 알립니다. 다만 매 프레임이 아니라 값이 뚜렷이 바뀔 때만 알립니다
- 교란 효과가 강하면 광과민성 문제가 생길 수 있으므로, 설정에서 끌 수 있게 합니다
