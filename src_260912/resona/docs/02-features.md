# 02. 기능 명세

각 기능에 식별자를 붙였습니다. 구현과 검수에서 이 식별자로 부릅니다.

## F-100 음악 입력

### F-101 음원 파일 로드

사용자가 오디오 파일을 끌어다 놓거나 클릭해서 선택하면 재생 준비를 마칩니다.

- 지원 형식: MP3, WAV, FLAC, OGG (브라우저 `decodeAudioData` 가 처리하는 범위)
- 파일은 브라우저 안에서만 디코딩합니다. 서버 업로드는 하지 않습니다
- 로드 후 파형 개요(peaks)를 만들어 탐색 막대에 표시합니다
- 파일명과 총 길이를 화면에 표시합니다

**수용 기준**: 5분짜리 MP3 를 끌어다 놓으면 3초 안에 파형이 그려지고 재생 버튼이 활성화됩니다.

### F-102 라인/마이크 입력

`getUserMedia` 로 오디오 입력 장치를 받습니다.

- 에코 제거, 잡음 억제, 자동 이득 조절을 모두 끕니다. 공연 음향을 그대로 측정해야 하기 때문입니다. 특히 자동 이득 조절이 켜지면 곡의 셈여림이 뭉개져 `arousal` 판정이 망가집니다
- 입력을 스피커로 되돌리지 않습니다. 하울링을 막기 위함입니다. 분석 버스에만 물립니다
- 권한이 거부되면 사유를 화면에 적고 다른 입력을 권합니다. 장치 없음(`NotFoundError`)과 API 미지원도 갈라서 안내합니다
- 입력 장치를 고를 수 있게 합니다. 오디오 인터페이스가 여럿 붙는 현장이 있습니다
- **소스를 바꾸는 것은 전체 초기화입니다.** 파일 ↔ 마이크 ↔ 데모 를 오갈 때 `bpm` 을 포함해 분석 버퍼를 전부 비웁니다 (`05-signal-processing.md` 3-5절). 탐색과 달리 부분 초기화가 아닙니다
- 끝나는 시각이 없는 입력이라 구간 반복(F-202)과 가사 `균등 배분` 을 쓸 수 없습니다. 잠그되 눌리게 두고 사유를 띄웁니다 (`03-screens.md` 01 절)

**수용 기준**: 마이크를 켜고 소리를 내면 RMS 값이 즉시 반응합니다.

### F-103 데모 신스

오디오 입력 없이 기능을 확인할 수 있도록 내장 신스가 리듬 패턴을 생성합니다.

- 킥, 스네어, 하이햇, 베이스, 패드를 오실레이터와 노이즈로 합성합니다
- 기본 템포 120 BPM, 4/4 박자
- 실제 오디오 신호로 만들어 같은 분석 경로를 통과시킵니다. 값을 가짜로 넣지 않습니다

**수용 기준**: 데모를 켜면 BPM 이 120 근처로 수렴하고 비트가 규칙적으로 뜁니다.

### F-104 스템 파일 로드 (선택)

분리된 스템 오디오 파일 네 개(드럼·베이스·보컬·기타)를 각각 올릴 수 있습니다.

- 네 파일을 동기 재생하고 각각의 RMS 를 측정합니다
- 트랙별 음소거 토글을 제공합니다
- 스템을 쓰지 않을 때는 F-503 의 추정 스템으로 대체합니다

**수용 기준**: 스템 네 개를 올리면 각 트랙의 레벨 미터가 독립적으로 움직입니다.

## F-200 재생 제어

### F-201 트랜스포트

재생, 일시정지, 정지, 탐색을 제공합니다.

- 스페이스바로 재생과 일시정지를 전환합니다
- 탐색 막대를 클릭하면 그 지점으로 이동합니다
- 현재 시각과 총 길이를 `MM:SS.CS` 형식으로 표시합니다

### F-202 구간 반복

시작점과 끝점을 지정해 반복 재생합니다. 리허설에서 특정 구간의 연출을 조정할 때 씁니다.

**수용 기준**: A 지점과 B 지점을 찍으면 그 구간만 계속 반복됩니다.

## F-300 관객 입력

관객 입력의 두 방식은 같은 인터페이스를 구현합니다. 상세는 `05-signal-processing.md` 4절을 따릅니다.

```ts
interface AudienceSource {
  readonly kind: 'camera' | 'microphone' | 'simulation' | 'none';
  start(): Promise<void>;
  stop(): void;
  /** 매 프레임 호출. 0~1 로 정규화된 관객 에너지를 반환합니다. */
  read(dt: number): number;
  /** 보정 진행률 0~1. 1 이면 보정 완료입니다. */
  readonly calibration: number;
}
```

### F-301 카메라 모션 방식

객석을 향한 카메라 영상에서 움직임의 양을 측정합니다.

- 영상을 64×36 격자로 축소해 밝기 변화량만 계산합니다
- 원본 프레임은 저장하지도 전송하지도 않습니다
- 조명 변화가 전체 움직임으로 오인되지 않도록 전역 밝기 변화를 먼저 제거합니다
- 화면에 격자 시각화와 "NO FRAMES STORED" 표시를 둡니다

**수용 기준**: 카메라 앞에서 손을 흔들면 에너지 값이 오르고, 조명을 껐다 켜도 급등하지 않습니다.

### F-302 마이크 오디오 방식

객석을 향한 마이크에서 박수와 환호의 강도를 측정합니다.

- 2~8kHz 대역의 트랜지언트 밀도로 박수를 추정합니다
- 광대역 지속음의 세기로 환호를 추정합니다
- 무대 음향이 섞여 들어오는 것을 줄이기 위해 음악 트랙의 스펙트럼을 참조해 상관이 높은 성분을 감쇠합니다

**이 기능은 「이후 과제」입니다** (`07-roadmap.md`). 04 관객 패널의 `마이크` 버튼은 자리를 잡아 두되, 누르면 아직 만들지 않았다는 사유를 표시합니다. 버튼을 아예 막아 두면 눌러도 아무 일이 없어 고장으로 보입니다.

**수용 기준**: 박수를 치면 에너지가 오르고, 음악만 크게 틀었을 때는 크게 오르지 않습니다.

### F-303 관객 시뮬레이션

카메라와 마이크 없이 기능을 확인하기 위한 가상 입력입니다.

- 느리게 변하는 기저 에너지와 약 128 BPM 의 맥동을 합성합니다
- 사용자가 슬라이더로 에너지를 직접 밀어 올릴 수 있습니다
- **자동 보정(F-304)을 건너뜁니다.** 값이 이미 0~1 이라 정규화할 대상이 없고, 20초를 기다리게 하면 카메라 없이 개발한다는 목적에 어긋납니다. 어택·릴리스 평활은 그대로 겁니다

**수용 기준**: 시뮬레이션을 켜고 슬라이더를 올리면 연출 강도가 따라 오릅니다. 보정 진행률을 기다리지 않고 즉시 값이 나옵니다.

### F-304 자동 보정

관객 에너지는 공연장마다 기준이 다르므로 최근 60초의 분포로 자동 보정합니다.

- 하위 5퍼센타일을 0, 상위 95퍼센타일을 1 로 잡습니다
- 보정이 끝나기 전에는 진행률을 화면에 표시합니다
- 수동 재보정 버튼을 제공합니다 (`R` 키)
- **재보정은 분포 이력만 비웁니다. 입력 소스를 재시작하지 않습니다.** 소스를 다시 열면 `getUserMedia` 가 다시 호출되어 스트림이 끊기고 권한을 다시 물을 수 있습니다. 공연 중에 재보정 한 번으로 카메라가 죽습니다
- 시뮬레이션 방식은 이 기능을 건너뜁니다 (F-303)

**수용 기준**: 조용한 상태로 20초를 두면 보정 진행률이 오르고, 완료 후 박수를 치면 1 에 가까운 값이 나옵니다.

## F-400 연출 번역

**이 프로젝트의 핵심입니다.** 알고리즘 상세는 `05-signal-processing.md` 6절에 있습니다.

### F-401 음악 상태 판정

음악 분석값을 종합해 현재 상태를 하나로 판정합니다.

- 상태: `SILENT`, `CALM`, `GROOVE`, `BUILD`, `PEAK`, `BREAK`
- 검사 순서는 `SILENT` → `BREAK` → **`BUILD`** → `PEAK` → `GROOVE` → `CALM` 입니다. `BUILD` 가 `PEAK` 보다 앞입니다. 세기 하나로는 두 구간이 갈리지 않고 기울기의 부호가 가르기 때문입니다
- `BUILD` 조건은 `rmsSlope > 0.008` 하나입니다. **플럭스를 조건에 넣지 마십시오.** 플럭스는 세기가 아니라 음색 변화에 반응해서, 실측에서 `BUILD` 보다 `PEAK` 구간에서 더 자주 통과합니다
- **최근 1.2초 창에서 과반을 차지한 상태로 전환하고, 바뀐 뒤 최소 1.2초를 유지합니다.** "1.2초 연속"이 아닙니다. 프레임 단위 판정에는 다른 상태가 7~11% 섞여 나오므로, 연속을 요구하면 우세한 상태도 문턱을 못 넘습니다
- `SILENT` 은 즉시 채택합니다. 조건 자체에 0.5초 지속이 들어 있습니다
- `BREAK` 은 즉시 채택하고 최소 0.8초를 유지합니다. 음악이 끊긴 순간은 무대에서 가장 극적이라 1.2초를 기다리면 늦은 티가 납니다
- `PEAK` 판정은 시정수 0.4초의 `rmsSlow` 를 씁니다. `rms`(40ms)는 킥마다 요동치고, `peakDecay` 는 평활이 아니라 홀드라 센 구간과 보통 구간이 갈리지 않습니다
- `PEAK` 에 `bands[HI]` 조건을 두지 않습니다. 음색의 밝기는 분위기 판정(F-404)의 `valence` 가 전담합니다

### F-402 연출 파라미터 산출

음악 상태와 관객 에너지를 결합해 다음 값을 만듭니다. 모두 0~1 입니다.

| 파라미터 | 뜻 | 주 결정 요인 |
|---|---|---|
| `density` | 화면 요소의 밀도 | 음악 상태 × 관객 |
| `scale` | 요소의 크기 | 베이스 대역 × 관객 |
| `speed` | 움직임의 속도 | BPM 및 비트 위상 |
| `brightness` | 밝기 | RMS × 관객 |
| `expansion` | 확산 정도 | 관객 에너지 |
| `glitch` | 교란 강도 | 온셋 및 상태 전이 |
| `dreaminess` | 몽환도 (0 날카로움 ↔ 1 번짐) | 곡의 격렬함 (F-404) |
| `palette` | 색 다섯 개의 묶음 | 곡의 밝기 (F-404, F-1002) |
| `hue` | 색상 각도 | 팔레트의 강조색. 외부 연동 하위 호환용입니다 |

관객 에너지가 곱해지는 자리를 코드에 명시적으로 남깁니다. 이 결합이 프로젝트의 이유이므로, 나중에 읽는 사람이 어디서 합쳐지는지 바로 찾을 수 있어야 합니다.

### F-303-2 템포 수동 확정 (탭 템포·잠금)

자동 추정은 실제 음악에서 배수 관계 오류를 완전히 피할 수 없습니다. 오퍼레이터가 직접 확정할 수 있어야 공연에서 쓸 수 있습니다. 상용 VJ 소프트웨어가 모두 갖춘 기능입니다.

- **탭 템포**: `T` 키를 박자에 맞춰 네 번 이상 두드리면 그 간격의 중앙값을 BPM 으로 확정합니다. 평균이 아니라 중앙값을 쓰는 이유는 한 번 늦게 친 탭이 전체를 끌지 않게 하기 위해서입니다. 2초 이상 쉬면 다시 셉니다
- **사람이 개입하면 자동으로 잠깁니다**: 탭이 네 번째에 도달하는 순간, 그리고 배수 보정 버튼을 누르는 순간 잠금이 켜집니다. 이것이 없으면 확정한 값이 0.4초 뒤 자동 추정에 덮어씌워져, 조작해도 아무 일도 일어나지 않는 것처럼 보입니다. 탭을 친다는 것 자체가 "내가 값을 정하겠다"는 의사이므로 그대로 존중합니다. 자동 추정으로 되돌아가려면 잠금을 직접 풀면 됩니다
- **잠금**: 자물쇠를 켜면 자동 추정이 값을 바꾸지 못합니다. 비트 위상 스냅은 계속 동작합니다
  - **BPM 이 없을 때는 잠글 수 없습니다.** 값이 `---` 인 상태에서는 버튼을 비활성화하고, 눌렀을 때 `먼저 T 를 네 번 두드려 템포를 정하세요` 를 안내합니다. 잠글 대상이 없는데 잠기면 무엇이 고정된 것인지 알 수 없습니다
  - **잠금 중에도 엔벨로프 수집과 추정 계산은 계속 돌립니다.** 결과를 화면 값에 적용하지 않을 뿐입니다. 이렇게 해야 잠금을 푸는 즉시 최신 추정으로 돌아옵니다. 계산까지 멈추면 풀었을 때 잠글 당시의 낡은 값이 그대로 남아, 자동 추정이 죽은 것처럼 보입니다
  - 잠금 해제 시 추정값과 화면 값이 다르면 갱신 폭 규칙에 따라 따라갑니다
  - **잠금 버튼은 지금 화면에 보이는 값을 고정합니다.** 이전에 확정했던 값으로 되돌아가지 않습니다. 자물쇠는 현재 상태를 붙잡는다는 뜻이고, 자동 추정을 지켜보다 맞는 값이 나왔을 때 잠그는 것이 실제 사용 흐름입니다. 이전 값으로 돌아가려면 다시 탭하면 됩니다
  - **새 파일을 로드하면 잠금을 풉니다.** 곡이 바뀌면 템포도 바뀌므로 앞 곡의 값을 물릴 이유가 없습니다. 다만 프리셋 적용은 예외이며, 프리셋에 저장된 `tempoLocked` · `lockedBpm` 을 그대로 씁니다
  - **잠금 중에는 신뢰도와 무관하게 BPM 을 표시합니다.** 사람이 정한 값이므로 `03-screens.md` 의 "신뢰도 0 이면 `---`" 규칙을 적용하지 않습니다. 신뢰도 칸에는 숫자 대신 `수동` 을 표시해, 자동 추정의 확신도와 섞이지 않게 합니다
- **배수 보정**: `×2` `÷2` `×1.5` `÷1.5` 버튼으로 배수 관계 오류를 즉시 바로잡습니다
- **프리셋 저장**: 확정한 BPM 과 잠금 여부를 프리셋에 함께 저장합니다 (`06-data-model.md` 의 `locked_bpm` · `tempo_locked`). 리허설에서 한 번 맞추면 공연에서 그대로 씁니다
- **조작부 위치**: 하단 트랜스포트의 재생 제어 옆에 둡니다. 공연 중 손이 가는 조작이므로 오른쪽 레일의 진단용 패널이 아니라 재생 조작 곁에 있어야 합니다

**수용 기준**: 자동 추정이 틀린 곡에서 탭으로 맞춘 뒤 잠그면, 곡이 끝날 때까지 그 값이 유지되고 비트가 음악과 맞습니다.

### F-403 관객 영향력 조절

관객 신호가 연출에 얼마나 개입할지를 0~100% 로 조절합니다.

- 0% 로 두면 음악만으로 동작합니다. 관객 입력이 없거나 신뢰할 수 없을 때 씁니다
- 기본값은 60% 입니다
- 조절 결과가 화면에 즉시 반영되어야 합니다

**수용 기준**: 영향력을 0 으로 내리면 관객이 아무리 움직여도 화면이 변하지 않고, 100 으로 올리면 크게 변합니다.

### F-404 곡 분위기 판정

F-401 의 음악 상태가 "지금 이 순간이 얼마나 센가" 를 본다면, 이 기능은 "이 곡이 어떤 성격인가" 를 봅니다. 발라드의 후렴과 댄스곡의 후렴은 둘 다 `PEAK` 이지만 같은 화면이면 안 됩니다.

두 실수를 산출합니다. 알고리즘은 `05-signal-processing.md` 7절에 있습니다.

| 축 | 뜻 | 무엇을 정하는가 |
|---|---|---|
| `valence` | 밝음 ↔ 어두움 (0~1) | 색 — 어떤 팔레트를 쓸지 |
| `arousal` | 격렬함 ↔ 잔잔함 (0~1) | 결 — 화면이 몽환적일지 날카로울지 |

- `valence` 는 크로마 12빈으로 장조·단조를 근사하고 센트로이드를 더해 구합니다. 시상수 6초로 천천히 움직입니다
- `arousal` 은 RMS·BPM·온셋 밀도·고역으로 구합니다. 시상수 3초로 `valence` 보다 빠르게 반응합니다
- 두 축의 평면을 다섯 구역으로 나눠 이름을 붙입니다. `침잠` `평온` `희망` `격정` `중립`
- **이름은 표시용이고, 연출은 두 실수를 직접 씁니다.** 이름으로 분기하면 경계에서 화면이 끊깁니다

**수용 기준**: 발라드와 댄스곡을 번갈아 걸면 `arousal` 이 뚜렷하게 갈리고, 장조 곡과 단조 곡을 걸면 `valence` 가 갈립니다. 곡 안에서 값이 초 단위로 튀지 않습니다.

### F-405 몽환도

`arousal` 을 뒤집어 무대 씬의 결을 정하는 값입니다.

- `dreaminess = (1 − arousal) × (1 − 실효관객값 × 0.35)`
- 0 이면 날카롭고 빠른 화면, 1 이면 번지고 느린 화면입니다
- 어느 자리에 어떻게 들어가는지는 `03-screens.md` 의 무대 씬 절에 표로 있습니다
- **오퍼레이터가 직접 고정할 수 있습니다.** 리허설에서 정한 값을 프리셋에 저장합니다

**수용 기준**: 잔잔한 곡에서 화면이 크게 번지고 느리게 흐르며, 신나는 곡에서 입자가 빠르게 돌고 윤곽이 또렷해집니다. 같은 곡에서 관객 에너지를 올리면 조금 더 날카로워집니다.

## F-500 화면 렌더링

씬 여섯 가지를 전환하며 씁니다. 상세 배치는 `03-screens.md` 를 따릅니다.

**셋은 진단용, 셋은 무대용입니다.** 직조·관객·스펙트럼은 분석이 제대로 도는지 확인하는 화면이고, 가사·합성·무대가 관객에게 보이는 화면입니다.

씬 버튼은 **용도가 같은 것끼리 묶어 두 줄로** 배열합니다. 무대용(`무대` `합성` `가사`)이 위, 진단용(`직조` `스펙트럼` `관객`)이 아래입니다. 숫자키는 배열 순서 그대로 `1`~`6` 이고, `1` 이 무대인 것은 공연 중에 손이 가장 자주 가는 자리이기 때문입니다.

각 버튼 아래에 그 씬이 무엇을 보여 주는지 네 글자에서 여섯 글자로 적습니다.

### F-501 직조 (WEAVE)
비트마다 한 줄씩 쌓이는 가로 띠로 곡의 진행을 직물처럼 그립니다. 각 줄은 그 순간의 스템 네 값을 담습니다.

### F-502 가사 (TYPE)
현재 가사 줄을 큰 활자로 띄우고, 재생 진행에 맞춰 단어 단위로 강조합니다.

### F-503 관객 (FACES)
관객 격자 또는 검출된 영역을 타일로 배열합니다. 관객 에너지가 타일의 밝기와 배치에 반영됩니다.

**진단용입니다.** 신호가 실제로 들어오는지 오퍼레이터가 확인하는 용도이며 무대에 거는 화면이 아닙니다.

### F-504 스펙트럼 (SPECTRUM)
주파수 스펙트럼과 6밴드 레벨을 그립니다. 진단 목적이 큽니다.

### F-505 합성 (COMPOSITE)
바탕(무대 또는 직조) 위에 가사를 얹습니다. 두 층입니다.

**관객 격자를 겹치지 않습니다.** 관객은 이 씬에도 값으로만 들어옵니다. 바탕 씬이 이미 `expansion` 과 `dreaminess` 로 관객을 받고 있으므로, 그림을 한 겹 더 얹으면 관객이 두 번 들어가는 셈이 됩니다. 관객이 그림으로 나오는 자리는 관객 씬(F-503) 하나뿐이고 그것은 진단용입니다.

### F-506 출력 창 분리

렌더링 화면만 별도 창으로 띄웁니다. 콘솔은 오퍼레이터 화면에, 출력은 프로젝터에 보내기 위함입니다.

**수용 기준**: 출력 창을 열어 두 번째 디스플레이로 옮기면 콘솔 조작이 그대로 반영됩니다.

### F-506-2 콘솔이 가려져도 출력은 계속 돕니다

브라우저는 최소화되거나 뒤로 간 창의 `requestAnimationFrame` 을 멈춥니다. 분석과 렌더가 콘솔의 rAF 한 줄에 얹혀 있으면, 오퍼레이터가 콘솔을 최소화하거나 다른 탭으로 넘어가는 순간 무대 화면이 정지합니다.

두 디스플레이에 창을 나란히 띄우는 정상 배치에서는 둘 다 보이므로 문제가 없습니다. 그러나 공연 중에 오퍼레이터가 파일 탐색기나 다른 프로그램을 잠깐 앞으로 부르는 일은 반드시 일어납니다. **한 부분이 실패해도 화면은 계속 돌아야 한다는 원칙에 걸립니다.**

- **분석 루프의 구동원을 콘솔의 rAF 에서 떼어 냅니다.** `lib/audio/analyser.worklet.js` 를 약 60Hz 시계로 만들어 `dt` 를 메인 스레드로 보내고, 분석 자체는 지금처럼 메인 스레드에서 `AnalyserNode` 로 합니다. **특징 추출을 워크렛으로 옮기지 않습니다** — `AnalyserNode` 를 버리면 온셋 임계값과 BPM 계수를 전부 다시 맞춰야 합니다
- **출력 창은 자기 rAF 로 그립니다.** 콘솔이 보내 준 값을 받아 자기 창에서 그리면, 콘솔이 가려져도 출력 창이 앞에 있는 한 계속 그려집니다
- 콘솔의 rAF 는 콘솔 미리보기와 수치 표시에만 씁니다. 여기가 멈춰도 무대는 영향을 받지 않습니다
- 출력 창이 값을 0.5초 이상 못 받으면 마지막 값으로 계속 그리되, 화면 구석에 아무것도 표시하지 않습니다. 관객이 보는 화면이므로 오류 표시를 띄우지 않습니다

**수용 기준**: 출력 창을 열어 둔 채 콘솔 창을 최소화하면 출력 창의 화면이 계속 움직이고, 콘솔을 다시 열었을 때 음악과 맞는 자리에서 이어집니다.

### F-507 무대 (BLOOM) ★

**공연 본편에 거는 화면입니다.** 앞의 다섯 씬 가운데 직조·관객·스펙트럼은 분석이 제대로 도는지 확인하는 진단용이고, 무대에 걸 화면은 따로 있어야 합니다.

WebGL2 로 세 층을 그립니다. 상세는 `03-screens.md` 의 무대 씬 절에 있습니다.

- 배경 유체 — 도메인 워핑 노이즈. 몽환적일수록 크게 휘어지고 느리게 흐릅니다
- 입자 — 상태를 저장하지 않고 정점 셰이더에서 위치를 계산합니다. 비트마다 바깥으로 퍼집니다
- 블룸 — 밝은 부분을 1/4 해상도에서 블러해 가산 합성합니다
- 색은 전부 팔레트의 역할 다섯 개에서 옵니다 (F-1000)
- 숫자·눈금·라벨을 그리지 않습니다

**수용 기준**: 잔잔한 곡을 걸면 색이 번지며 천천히 흐르고, 신나는 곡을 걸면 입자가 빠르게 돌며 비트마다 바깥으로 터집니다. 두 곡의 화면이 서로 다른 곡의 것으로 보입니다. 1920×1080 출력에서 60fps 를 유지합니다.

### F-508 씬 파라미터 실시간 조절

선택된 씬의 조절 값을 리허설 중에 바꿉니다. 원본 프로토타입에 있던 기능인데 이번 명세에서 빠져 있던 것을 채웁니다.

- 공통: `강도` `잔상` `그레인` `교란`
- 직조: `경사` `위사` `장력` `직조 속도` `스템 분리`
- 무대: `입자 수 상한` `유체 워핑` `블룸 반경` `블룸 세기` `몽환도 고정`
- 슬라이더마다 `자동` 되돌림 버튼을 둡니다
- 손댄 슬라이더는 손잡이 색을 바꿔 표시합니다
- 모든 값이 프리셋에 저장됩니다

직조 파라미터를 바꿀 때는 이미 쌓인 행을 그대로 두고 새 행부터 적용합니다. 소급 재계산하면 천이 한 번에 뒤틀립니다.

**수용 기준**: 재생 중에 경사 실 개수를 48 에서 80 으로 올리면 이미 짜인 부분은 그대로 있고 새로 쌓이는 부분부터 촘촘해집니다.

## F-600 가사 큐

### F-601 LRC 로드
`[mm:ss.xx]` 형식의 가사 파일을 읽어 시각과 줄을 대응시킵니다.

소수 자리는 없거나(`[mm:ss]`) 한 자리부터 세 자리까지 모두 받습니다. 한 줄 앞에 시각이 여럿 붙어 있으면(후렴) 그만큼 큐를 만듭니다. 가사 본문 안의 대괄호는 지우지 않습니다. `[ti:] [ar:] [al:] [by:]` 같은 머리 태그는 가사로 내보내지 않습니다. 파일에 적힌 순서와 무관하게 시각으로 정렬합니다.

**`[offset:]` 은 빼는 방향입니다.** `[offset:+500]` 이면 모든 줄이 0.5초 **일찍** 뜹니다. 파일에 `[00:10.00]` 으로 적힌 줄이 9.5초에 올라옵니다. 가사가 음악보다 늦게 보일 때 앞으로 당기는 것이 이 태그의 본래 용도이고, 편집기(F-603)의 전체 오프셋 버튼과 부호가 반대라는 점만 유의합니다. 편집기 쪽은 타임스탬프 자체를 고치므로 `+0.1s` 를 누르면 가사가 늦게 뜹니다.

### F-602 진행 표시
현재 줄, 다음 줄, 줄 안에서의 진행률(0~1), 현재 단어 인덱스를 산출합니다.

**수용 기준**: 재생 중 가사가 음악과 맞게 넘어갑니다.

### F-603 가사 직접 입력과 편집

가사 파일을 미리 만들어 오지 못한 곡이 리허설에 올라옵니다. 그 자리에서 만들 수 있어야 합니다.

- LRC 원문을 붙여 넣고 `파싱`. **비어 있지 않은 모든 줄이 큐가 됩니다** — 시각이 안 붙은 줄은 시각 미정(`t: null`)으로 남습니다
- 타임스탬프 없는 순수 가사를 붙여 넣고 `길이에 균등 배분` 으로 출발점을 만듭니다. **시각 미정 줄만 대상입니다**
- 줄 목록에서 타임스탬프와 가사를 직접 고치고, 줄을 지우고, 재생 위치에 줄을 더합니다
- 전체 오프셋을 `−0.1s` `+0.1s` 로 밀어 한 번에 맞춥니다

**원문 영역은 지금 큐를 비춥니다.** 둘이 따로 놀면 불러온 가사 아래에 한 줄을 적고 `파싱` 을 눌렀을 때 스무 줄이 그 한 줄로 바뀝니다. 비추는 규칙은 `03-screens.md` 03 절의 표에 있습니다.

시각 미정 줄을 파싱에서 버리면 `길이에 균등 배분` 이 나눌 대상이 이미 사라져 두 기능이 서로를 무효로 만듭니다. 큐에 남겨 두고 재생과 내보내기에서만 건너뜁니다.

### F-604 탭으로 타임스탬프 찍기

재생하면서 가사가 넘어가는 순간마다 키를 눌러 시각을 기록합니다.

- 탭 모드를 켜면 `Space` 가 "현재 줄에 지금 시각 찍기" 로 바뀌고, 찍을 때마다 다음 줄로 내려갑니다
- **켜는 즉시 화면 상단에 붉은 배너를 띄웁니다.** `탭 모드 — Space 는 타임스탬프 찍기 · ESC 로 나가기`
- `Space` 는 평소 재생과 일시정지에 쓰는 키입니다. 배너 없이 뜻을 바꾸면 재생을 멈추려다 가사를 망가뜨립니다. **이 배너는 선택 사항이 아닙니다**
- `ESC` 또는 토글 해제로 빠져나옵니다

**수용 기준**: 탭 모드를 켜고 곡을 재생하며 스무 줄을 찍은 뒤 모드를 끄면, 그 타임스탬프대로 가사가 넘어갑니다. 모드를 끈 뒤 `Space` 는 다시 재생과 일시정지로 동작합니다.

### F-605 LRC 내보내기와 저장

- `.lrc` 파일로 내려받습니다. 편집기(6-C)에서 구현합니다
- Supabase 의 `lyrics` 에 곡과 묶어 저장합니다. **저장은 7단계에서 구현합니다.** 6-C 는 내보내기까지로 닫습니다. Supabase 연결이 7단계에 있어서, 저장을 6-C 에 두면 스키마와 RLS 가 앞으로 끌려옵니다

`[offset:]` 을 쓰지 않습니다. 편집기의 전체 오프셋은 타임스탬프 자체를 밀어 둔 것이라 이미 각 줄에 들어가 있고, 태그로 한 번 더 적으면 다시 읽을 때 두 번 밀립니다. 부호까지 반대라(F-601) 두 배가 아니라 엉뚱한 자리로 갑니다.

편집기가 만든 시각은 1/100초에 맞춰 두므로 왕복이 정확히 맞습니다 (`03-screens.md` 03 절). 소수 세 자리로 적힌 남의 파일을 읽어 그대로 내보내면 1/100초로 잘립니다 — 형식이 담을 수 있는 한계입니다.

시각 미정 줄은 빼고 내보냅니다. LRC 는 시각이 있는 줄만 담는 형식이라 미정 줄을 시각 없이 적으면 다른 도구가 읽지 못합니다. 몇 줄을 뺐는지 알립니다.

**수용 기준**: 내보낸 파일을 다시 올리면 같은 가사 큐가 됩니다.

## F-700 프리셋

**음원 파일은 저장하지 않습니다.** 서버에 올라가는 것은 프리셋과 가사 큐뿐입니다. 곡은 공연 때마다 오퍼레이터가 로컬에서 열고, 앱은 `file_hash`(파일 이름과 크기로 만든 해시)로 "그 곡이구나" 하고 알아봅니다 (F-703). 그래서 프리셋을 불러와도 음원은 따라오지 않습니다 — 같은 파일을 다시 열어야 합니다.

01 소스 입력의 `파일은 브라우저 안에서만 디코딩됩니다. 서버 업로드·저장 없음.` 이 그대로 유효합니다. 저장 기능이 붙었다고 달라지지 않습니다.

### F-701 저장
현재 설정(씬, 감도, 관객 영향력, 팔레트, 씬 파라미터, 몽환도 고정값, 임계값)을 이름을 붙여 저장합니다.

### F-702 불러오기
저장한 프리셋 목록에서 선택해 즉시 적용합니다.

### F-703 곡 연결
프리셋을 곡 파일명과 연결해 두면, 그 곡을 로드할 때 자동으로 제안합니다.

**적용 순서를 지켜야 합니다.** 파일 로드는 템포 잠금을 푸는 동작이므로, 프리셋을 먼저 적용하면 그 값이 곧바로 지워집니다.

```
loadFile  →  프리셋 제안  →  applyPreset
```

이 순서가 뒤바뀌면 프리셋에 저장한 `lockedBpm` · `tempoLocked` 가 반영되지 않습니다.

**수용 기준**: 프리셋을 저장하고 페이지를 새로 고친 뒤 불러오면 같은 상태가 됩니다.

## F-800 외부 연동

**원본 프로토타입에 이미 있던 기능입니다.** `resona.html` 의 「08 · TouchDesigner 라우팅」 패널이 WebSocket 송출·형식 전환·채널 표·연동 스니펫을 모두 갖추고 있습니다. 이번 단계는 그것을 옮기는 일이며, 다만 **내보내는 값을 바꿉니다** (F-802).

### F-801 WebSocket 송출

분석값과 연출 파라미터를 내보냅니다.

- 기본 주소 `ws://localhost:9980`
- 형식 두 가지: JSON 객체, OSC 스타일 평문
- 송출 주기는 기본 초당 60회이고 화면에서 5~120 사이로 조절합니다. 원본에서 실제로 쓰던 값입니다. 받는 쪽이 버거워하면 내리라고 두는 슬라이더입니다
- 연결 상태를 `OFFLINE` · `CONNECTING` · `LIVE` 로 표시합니다
- 끊기면 자동으로 다시 붙습니다. 간격은 1초에서 시작해 두 배씩 늘리고 최대 10초에서 멈춥니다. 해제 버튼으로 끊은 경우에는 시도하지 않습니다

**자동 재연결은 이번에 새로 만드는 것입니다.** 원본은 `onclose` 에서 상태 표시만 바꾸고 다시 붙지 않아, 공연 중에 TouchDesigner 를 껐다 켜면 사람이 연결 버튼을 다시 눌러야 했습니다. 무대 뒤에서 그 버튼을 찾는 상황을 만들지 않습니다.

**주의**: 브라우저 보안 정책 때문에 HTTPS 로 배포된 페이지에서는 로컬 소켓에 연결할 수 없습니다. 외부 연동을 쓸 때는 로컬 실행(`npm run dev`)으로 안내합니다. 이 제약을 화면에도 적어 둡니다.

### F-802 채널 목록

송출하는 값의 이름과 현재 값을 표로 보여 줍니다. 연동 쪽에서 무엇을 받을 수 있는지 확인하는 용도입니다.

**원본의 채널 표를 그대로 쓰지 않습니다.** 원본은 `face/count` 와 `face/max` 처럼 관객 카메라의 날값을 내보냈습니다. 이 프로젝트에서 관객은 0~1 로 정규화되어 연출을 증폭하는 값이고, 그 결과가 `DirectionParams` 입니다. 외부로 나가야 하는 것은 분석값이 아니라 **연출값**입니다. 얼굴 수를 받아서 TouchDesigner 쪽이 다시 연출을 계산하면, 이 프로젝트가 `translate.ts` 한 곳에 모아 둔 결합 규칙이 무대 밖에서 한 번 더 갈라집니다.

| 묶음 | 채널 | 값 |
|---|---|---|
| 시간·박자 | `/resona/time` `bpm` `bpm_conf` `beat` `bar` `beat_in_bar` `phase` | 숫자 |
| 음량·음색 | `/resona/rms` `peak` `flux` `centroid` `onset` `onset_pulse` `transition_pulse` | 숫자 |
| 밴드 | `/resona/band/sub` `low` `lmid` `mid` `hi` `air` | 0~1 |
| 스템 | `/resona/stem/drums` `bass` `vocal` `other` | 0~1 |
| 곡 성격 | `/resona/state` `mood/valence` `mood/arousal` `mood/conf` | 숫자 |
| | `/resona/mood/name` | `DEEP` `SERENE` `RADIANT` `FERVENT` `NEUTRAL` |
| 관객 | `/resona/audience` `audience/calibration` `influence` | 0~1 |
| | `/resona/audience/state` | `DORMANT` `STIRRING` `ACTIVE` `SURGE` |
| 연출 | `/resona/dir/density` `scale` `speed` `brightness` `expansion` `glitch` `dreaminess` | 0~1 |
| 색 | `/resona/palette/bg` `deep` `base` `accent` `hot` | `#RRGGBB` |
| | `/resona/hue` | 0~1. `accent` 의 색상각 ÷ 360 |
| 가사 | `/resona/lyric/ordinal` `total` `prog` | 숫자 |
| | `/resona/lyric/line` `next` `word` | 문자열 |
| 화면 | `/resona/scene` | `weave` `bloom` `composite` `type` `faces` `spectrum` |
| | `/resona/blackout` | 0 또는 1 |

`/resona/audience` 와 `/resona/influence` 를 함께 보내므로, 받는 쪽에서 관객 기여분을 되짚을 수 있습니다. `musicOnly` 는 화면 표시용이라 내보내지 않습니다.

`/resona/lyric/ordinal` 은 **시각이 붙은 줄만 센 번호**입니다 (`06-data-model.md` `LyricCue`). 원본의 `lyric/index` 는 배열 번호였습니다. 시각 미정 줄이 섞이면 두 값이 어긋나므로 이름을 바꿨습니다.

`/resona/hue` 는 원본에서 색을 하나의 각도로 받던 연동을 위해 남겨 둔 자리입니다. 새로 붙이는 쪽은 `palette/*` 다섯을 쓰십시오.

**문자열 채널은 CHOP 으로 가지 않습니다.** TouchDesigner 쪽에서 숫자는 Constant CHOP, 문자열은 Table DAT 으로 갈라 받습니다. F-803 의 스니펫이 그렇게 나눠 둡니다.

### F-803 연동 스크립트 제공

TouchDesigner 쪽에 붙여 넣을 수 있는 파이썬 콜백 예제를 화면에서 복사할 수 있게 합니다. 원본의 스니펫을 바탕으로 하되, 위 표의 문자열 채널(`mood/name` · `audience/state` · `palette/*` · `lyric/line` · `lyric/next` · `lyric/word` · `scene`)이 Table DAT 으로 가도록 갱신합니다.

## F-1000 팔레트

**색을 다루는 기능입니다.** 원본 프로토타입은 톤 세 가지 중 하나를 고르는 방식이었습니다. 이번 확장에서는 색 다섯 개를 묶은 팔레트를 고르거나 직접 만들고, 곡의 분위기가 팔레트를 자동으로 고르게 합니다.

규칙은 `05-signal-processing.md` 8절, 화면은 `03-screens.md` 의 05 팔레트 패널에 있습니다.

### F-1001 팔레트와 컬러칩 편집

한 팔레트는 역할 다섯 개의 색으로 이루어집니다.

| 역할 | 쓰이는 곳 |
|---|---|
| `bg` 배경 | 무대 배경의 가장 어두운 자리 |
| `deep` 깊이 | 배경 유체의 어두운 층 |
| `base` 기본 | 입자와 실의 기본색 |
| `accent` 강조 | 가사의 현재 단어, 세로실, 밝은 입자 |
| `hot` 순간 | 비트가 오는 순간에만 짧게 나타나는 색 |

- 역할마다 컬러칩을 눌러 색상환과 슬라이더로 고르거나 HEX 를 직접 입력합니다
- 편집하는 동안 무대 미리보기에 즉시 반영합니다. 저장을 기다리게 하지 않습니다
- 기본 제공 여덟 개는 지울 수 없고, 고치면 사본이 만들어집니다
- 최근에 쓴 색 여덟 개를 스와치로 남깁니다
- **씬은 색을 직접 쓰지 않고 이 다섯 역할로만 그립니다.** 그래야 팔레트를 갈아 끼워도 씬 코드를 고칠 일이 없습니다

**수용 기준**: 팔레트의 `base` 를 노랑에서 파랑으로 바꾸면 무대 씬의 입자 색이 즉시 바뀌고, 다른 씬을 열어도 같은 팔레트가 적용되어 있습니다.

### F-1002 분위기에 따른 팔레트 자동 전환

곡의 `valence` (F-404) 가 색을 정합니다. 밝고 신나는 곡은 노랑 계열, 차분하고 어두운 곡은 파랑 계열로 갑니다.

- 팔레트마다 `(valence, arousal)` 평면의 앵커 좌표를 둡니다
- 현재 분위기 점에서 가장 가까운 앵커 **두 개**를 역거리로 섞습니다. 하나만 고르면 경계에서 색이 툭 바뀝니다
- **색은 OKLab 공간에서 섞습니다.** sRGB 를 그대로 보간하면 파랑과 노랑 사이가 탁한 회색을 지나갑니다
- 목표 색이 바뀌어도 화면 색은 시상수 2.5초로 천천히 따라갑니다 (0.5~8초로 조절 가능). 공연 중 색이 한 프레임에 바뀌면 조명 사고처럼 보입니다
- **새 곡을 로드해도 색 보간기를 비우지 않습니다.** 곡이 바뀌는 순간이 색이 가장 크게 움직이는 자리라, 여기서 초기화하면 새 색이 한 프레임에 찍힙니다. 분위기 판정만 비웁니다
- **자동과 수동은 둘 중 하나입니다.** 자동이 켜져 있으면 분위기가 색을 온전히 정하고, 꺼져 있으면 고른 팔레트 하나만 씁니다. 섞지 않습니다
- **자동이 켜져 있으면 어느 카드에도 선택 표시가 없습니다.** 카드를 누르면 자동이 꺼지고 그 카드가 선택됩니다. 탭 템포(F-303-2)와 같은 원칙으로, 사람이 개입하면 자동이 물러납니다
- `자동` 을 토글로 끄면 직전 섞임에서 우세했던 팔레트가 선택됩니다
- 선택 팔레트의 기본값은 `MONO` 입니다. 자동을 처음부터 끄고 시작하면 원본과 같은 흑백에 빨강 강조 화면이 나옵니다
- 자동을 켜 두었을 때 지금 무엇이 섞이는지 글자로 보여 줍니다. `침잠 62% + 평온 38%` 형태입니다
- 어떤 팔레트를 자동 후보에 넣을지 사용자가 정합니다. 앵커 좌표도 끌어서 옮길 수 있습니다
- **기본 자동 후보는 네 모서리(`침잠` `평온` `격정` `희망`)뿐입니다.** `MONO` 는 평면 한가운데에 있고 `base` 가 무채색이라, 후보에 두면 거의 모든 곡에서 두 번째로 뽑혀 색을 바래게 만듭니다 (실측: 밝은 곡에서 `MONO 53% + 희망 47%` 로 섞여 탁한 갈색이 나왔습니다)
- 기본 팔레트를 고치면 사본이 원본의 자동 후보 여부를 물려받고 **원본은 후보에서 빠집니다.** 둘 다 남으면 앵커를 옮겨도 원본이 제자리에서 계속 뽑힙니다
- **관객은 색을 바꾸지 않습니다.** 관객이 색까지 바꾸면 연출가가 곡마다 잡아 둔 색채 계획이 무너집니다

**수용 기준**: 자동을 켜고 밝은 팝을 걸면 노랑 계열, 단조 발라드를 걸면 남색 계열이 잡힙니다. 곡이 바뀔 때 색이 즉시 튀지 않고 2~3초에 걸쳐 넘어갑니다. 자동을 끄면 고른 팔레트에 그대로 머뭅니다.

### F-1003 기본 팔레트 여덟

`침잠` `평온` `희망` `격정` `MONO` `심해` `노을` `설야` 를 기본으로 제공합니다. 색값은 `05-signal-processing.md` 8-2절 표에 있습니다.

앞의 넷만 분위기 이름과 짝을 이뤄 자동 선택의 앵커가 되고, 뒤의 넷은 수동 선택용입니다. 원본 프로토타입의 세 톤은 각각 `MONO`(`mono`), `격정`(`alert`), `평온`(`duo`) 으로 흡수됩니다.

**수용 기준**: 팔레트를 `MONO` 로 두고 직조 씬을 보면 원본과 같은 흑백에 빨강 강조 화면이 나옵니다.
