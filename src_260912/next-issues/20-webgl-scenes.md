## 목표

Canvas 2D 로 그리고 있는 씬들을 WebGL2 로 옮긴다. 합성 씬에서 프레임이 모자랄 때 손대는 자리다.

## 배경

지금은 무대 씬(BLOOM) 하나만 WebGL2 이고 직조·가사·관객·스펙트럼·합성은 Canvas 2D 다. 이렇게 나눈 것은 의도한 설계다. 진단용 씬은 화면에 크게 걸 일이 없고, 직조는 가는 실을 긋는 그림이라 2D 로도 충분하다.

**지금 프레임이 나오고 있다면 이 과제는 하지 마라.** 성능 문제가 실제로 생겼을 때 여는 자리다.

## 언제 착수하는가

아래 중 하나에 해당할 때다.

- 합성 씬을 1920×1080 출력 창에 걸었을 때 60fps 를 못 지킨다
- 잔상을 길게 준 상태에서 직조 씬이 30fps 아래로 떨어진다
- 출력 창과 콘솔을 동시에 띄웠을 때만 프레임이 깨진다

## 작업

- [ ] 어느 씬이 얼마나 먹는지 먼저 잰다. 씬별 프레임 시간을 09 리드아웃에 표시한다
- [ ] 가장 비싼 씬 하나만 옮긴다. 한꺼번에 옮기지 마라
- [ ] 무대 씬의 셰이더 파이프라인을 재사용한다
- [ ] 팔레트 역할 다섯을 유니폼으로 넘긴다. 씬 코드에 색을 박지 않는다
- [ ] 옮긴 뒤 같은 곡으로 이전 화면과 나란히 비교한다

## 완료 기준

- [ ] 옮긴 씬의 그림이 이전과 같아 보인다. 빨라지자고 그림이 달라지면 실패다
- [ ] 1920×1080 출력 창에서 60fps 를 지킨다
- [ ] WebGL2 컨텍스트를 못 얻는 환경에서 2D 로 되돌아간다
- [ ] 컨텍스트를 잃었다가 되찾아도 화면이 복구된다

## 주의

**컨텍스트 개수에 한계가 있다.** 브라우저마다 다르지만 열여섯 개 안팎이다. 콘솔과 출력 창에서 씬마다 컨텍스트를 새로 만들면 금세 찬다. 하나를 만들어 돌려 쓰는 구조로 간다.

**이 프로젝트는 수치가 아니라 화면이 기준이다.** 옮기고 나서 fps 숫자만 보지 말고, 실제로 곡을 걸어 이전과 같은 그림이 나오는지 눈으로 확인해라.
